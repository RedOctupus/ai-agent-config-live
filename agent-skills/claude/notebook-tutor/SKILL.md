# Notebook Tutor Skill

生成可直接运行的教学型 Jupyter Notebook。代码完整、步骤原子化、注释密集——专为会因空白格子产生厌学情绪的初学者设计。

---

## Phase 1：确定内容来源

### 来源类型判断

**类型 1：源文档驱动**
- 触发信号：用户提供了 PPT / PDF / Word / 代码文件等具体文档
- 操作：先解析文档提取内容结构，再基于文档内容生成 notebook
- 解析优先级：
  - `.pptx` → `python-pptx`（`pip install python-pptx`）
  - `.pdf` → Read 工具直接读取
  - `.ipynb` → Read 工具直接读取
  - 解析失败时：请用户用文字描述文档的主要内容/大纲，不强行工程化

**类型 2：主题/任务描述驱动**
- 触发信号：用户描述一个学习主题或任务，但没有提供具体文档
- 操作：直接根据描述规划 notebook 结构

### 必须收集的信息（最多问 2 个问题，其余使用默认值）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 目标受众水平 | 初级（零基础） | 影响注释密度和步骤粒度 |
| 编程语言/框架 | Python | 根据文档/主题自动判断 |
| 数据文件路径 | 与文档同目录 | 若任务涉及数据文件 |

## Phase 2：规划 Notebook 结构

在生成前，先内部完成以下规划：

1. **提炼教学骨架**：从文档或描述中识别 3-8 个核心概念/步骤
2. **确定代码执行链**：每步的输入输出是什么，变量如何传递
3. **拆分步骤**：每个核心概念再拆成若干「原子操作」（一个格子只做一件事）
4. **确认可运行性**：提前在脑中验证代码逻辑，确保每个格子独立运行不报错
5. **标记可视化节点**：识别哪些概念需要配图（见下方「数形结合原则」）

**步骤拆分原则（最重要）**：
- 「读取数据 → 查看数据 → 查看结构」是三个格子，不是一个
- 「创建对象 → 解释参数 → 执行操作 → 查看结果」是四个格子
- 宁可多 5 个格子，也不要一个格子做 2 件事
- 每个格子都有对应的 markdown 解释，用户知道「为什么要做这步」

---

## 数形结合原则（可视化辅助理解）

**核心思想**：凡是「用文字说了两句还说不清」的概念，必须配一张图。数学公式只告诉人「是什么」，图才能告诉人「为什么」和「长什么样」。

### 必须配图的场景

| 场景类型 | 示例 | 推荐图类型 |
|---------|------|----------|
| 函数变换的效果 | Fisher Z 把 r 拉伸了多少 | 变换前后的折线/散点对比图 |
| 算法的几何直觉 | PCA 找「最大方差方向」 | 散点图 + 箭头标注主成分方向 |
| 反例驱动理解 | 不标准化时 PCA 被大尺度特征主导 | 两列并排：不做 vs 做了的对比图 |
| 分布形状 | 数据是否接近正态 | 直方图 + 理论正态曲线叠加 |
| 数量关系 | 前 N 个主成分累积了多少信息 | 折线图（累积方差曲线）/ 柱状图（碎石图） |
| 操作前后对比 | 标准化前后数值范围变化 | 并排 boxplot 或 histogram |
| 结构/矩阵 | 200×200 脑区连接矩阵 | heatmap（热力图） |

### 可视化 Cell 的写法规范

每张图必须对应一个独立的 code cell，**不与计算逻辑混写**。格式如下：

```python
# ── 可视化：{这张图要回答的问题} ──────────────────────────

fig, ax = plt.subplots(figsize=(...))

# [绘图代码]

ax.set_title('{图标题：说明这张图展示了什么}')
ax.set_xlabel('{x轴含义}')
ax.set_ylabel('{y轴含义}')

plt.tight_layout()
plt.show()

# 读图说明（print 输出，引导用户看图）
print('💡 观察：{告诉用户应该注意图中哪个特征，以及它说明了什么}')
print('   结论：{从图中得出的核心结论}')
```

### 图的教学功能分类

**① 动机图（Before）**：在执行操作之前，先用图展示「不做这步会有什么问题」
- 例：在讲 StandardScaler 之前，先画「未标准化时 PCA 被高方差特征主导」的散点图

**② 验证图（After）**：执行操作之后，用图证明「做了之后问题解决了」
- 例：标准化后再画散点图，PC1 方向不再偏向某一特征

**③ 原理图（Why）**：展示数学函数的几何形状，帮助理解公式背后的直觉
- 例：画出 arctanh(x) 的曲线，标注「两端斜率大=拉伸」「中间斜率小=压缩」

**④ 结果图（What we got）**：展示最终提取的特征长什么样
- 例：PC1-PC2 散点图，碎石图，载荷热力图

### 「反例→正例」模式（最有效的教学方式）

对于「为什么要做这步」类问题，**一律使用并排对比图**：

```python
fig, axes = plt.subplots(1, 2, figsize=(12, 5))

# 左图：不做这步的结果（❌ 有问题）
axes[0].set_title('❌ 不做 XXX 的后果', color='red', fontweight='bold')
# [绘制有问题的状态]

# 右图：做了这步的结果（✅ 问题解决）
axes[1].set_title('✅ 做了 XXX 之后', color='green', fontweight='bold')
# [绘制解决后的状态]

plt.suptitle('为什么要做 XXX？', fontsize=13)
```

### 坐标轴必须有含义

- 不允许出现只写「x」「y」「feature」的坐标轴标签
- 必须写清楚：这个轴的数字代表的是**现实世界的什么东西**
- 例：`ax.set_xlabel('Pearson r（两脑区之间的功能连接强度）')`

## Phase 3：生成 Notebook

使用 `Write` 工具创建 `.ipynb` 文件，保存到**当前工作目录**（或文档所在目录）。

文件命名：`{主题-kebab-case}-tutorial.ipynb`（中文主题则用拼音或英文缩写）

### Notebook 整体结构

```
[标题 cell]        notebook 标题、适合人群、学习路线预览
[概述 cell]        今天要做什么、学完能做什么、步骤列表
[安装/导入 cell]   pip install + import，确保可运行
---
[第一步]
[第二步]
...
[第 N 步]
---
[总结 cell]        回顾所学，关键代码模板，下一步建议
```

---

### Cell 序列规范

每个「步骤」由以下格子序列构成：

```
[markdown]  ---
            # 第 X 步：{动词短语，说明做什么}

            {2-4 句话说明这步的目的和在整体流程中的位置}

            ## 核心概念（若有新概念则加此节）
            **{概念名}** 是指 {用一个生活类比解释}。
            用代码来说：{一句话映射到代码层面}

[markdown]  ## {X}.{Y} {这一小步的具体动作}

            {1-2 句说明这行/这段代码在做什么，以及为什么}

[code]      # {一句话说明这个格子做什么}
            # 关键参数说明：
            #   {param1} = {说明}
            #   {param2} = {说明}

            {完整可运行代码，<=20 行}

            # 预期输出：{具体说明会看到什么}
```

**代码格子规范**：
- 每行关键逻辑都有行内注释，解释「这行在做什么」
- 参数含义在注释中说明，不假设用户知道
- 结尾注明「预期输出」，用户知道成功长什么样
- 变量命名清晰，不用 `x`, `tmp`, `a`
- 代码可独立运行（不依赖未定义的变量）

**markdown 格子规范**：
- 用生活类比解释技术概念（「就像...一样」）
- **关键词加粗**，技术术语首次出现时附中文解释
- 每步结束后，简短说明「下一步我们要做什么」，形成叙事连贯感
- `---` 分隔大步骤

---

### 特殊格子规范

**标题格子**（第一个 markdown cell）：
```markdown
# {主题} 手把手教程

> **适合人群**：零基础初学者 | **语言**：{language} | **预计时间**：{N} 分钟

{一句话说明这个 notebook 学完能做什么}

---

## 今天的学习路线

1. {第一步简述}
2. {第二步简述}
...
N. {第 N 步简述}
```

**安装/导入格子**：
```python
# 第一步：安装必要的库（如果已安装，运行也不会出错）
!pip install {库名}  # {说明这个库是做什么的}

# 导入工具
from {模块} import {工具}  # {一句话说明这个工具的用途}

print("✅ 所有工具准备完毕！")
```

**总结格子**（最后一个 markdown cell）：
```markdown
---
# 🏆 恭喜完成！

## 你今天掌握了：

| 技能 | 一句话回顾 |
|------|-----------|
| {技能1} | {回顾} |
| {技能2} | {回顾} |

## 关键代码模板（复习用）

\`\`\`python
# 把所有关键步骤浓缩成一个可复用的代码块
\`\`\`

## 下一步
- [ ] {具体的下一个学习目标}
- [ ] {推荐资源或扩展方向}
```

## Phase 4：输出说明

Notebook 生成完毕后，向用户说明：

1. **文件路径**：`已生成：./{filename}.ipynb`
2. **运行方式**：VS Code 打开（需 Jupyter 扩展）/ Jupyter Lab / Google Colab 上传
3. **使用建议**：从第一个格子开始，**按顺序逐格运行**（Shift+Enter），遇到不懂的注释随时问我
4. **可选后续**：
   - 针对某一步深入讲解
   - 换一个数据集重新练习
   - 生成同主题的「进阶版」notebook（加入更多细节和边界处理）

---

## 质量检查清单

生成每个 cell 前自检：

- [ ] 这个格子只做**一件事**，不做两件
- [ ] 代码可以独立运行（不依赖后面格子的变量）
- [ ] 每行关键代码都有注释
- [ ] 关键参数在注释中有解释
- [ ] markdown 用了生活类比解释新概念
- [ ] 格子末尾告诉用户「接下来做什么」
- [ ] 整个 notebook 的变量名前后一致

**格子数量参考**：
- 3 个核心概念：约 25-35 个 cell
- 6 个核心概念：约 50-70 个 cell
- 宁多勿少，步骤越细，初学者越不会卡住

---

## 语言与风格规范

- **notebook 内容语言**：跟随用户提问语言（中文提问 → 中文 notebook）
- **代码注释**：与 notebook 语言一致
- **技术术语**：保留英文原词，首次出现时括号附中文解释（如：`VectorAssembler`（特征向量打包器））
- **语气**：轻松、鼓励性，用「我们」而非「你应该」，像一个坐在旁边的朋友在讲解
- **避免**：「如你所知」「显然」「很简单」等可能让初学者自我怀疑的措辞
