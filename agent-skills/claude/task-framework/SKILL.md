# Task Framework Builder

## 触发时机

用户描述一个新项目、新功能、新工作流，或明确询问"如何完成 XX 任务"时启动此流程。

---

## Phase 1：需求拆解

将用户需求分解为若干**能力维度**，常见维度包括：

- 网络访问（搜索 / 抓取网页）
- 文件处理（读写 / 转换文档）
- 数据库查询
- 代码执行 / 测试
- 外部 API 调用
- 浏览器自动化
- 数据可视化
- 版本控制

列出本任务涉及的维度，每个维度进入 Phase 2 进行工具选型。

---

## Phase 2：工具选型

为每个能力维度列出候选工具，**优先列 MCP，其次列 CLI**（MCP 有结构化 schema，调用更安全）。

**优先级规则**（从高到低）：

1. 本地已有 MCP → 直接使用
2. 本地已有 CLI → 直接使用
3. skills.sh 安装量 > 10k 的工具 → 推荐下载
4. 其他工具 → 列出并说明理由，等待用户选择

对每个候选工具注明：用途、覆盖面（安装量或社区规模）、是否需要 API Key。

---

## Phase 3：本地环境检查

**并行执行以下检查**：

### 检查已注册 MCP

```bash
cat ~/.claude/settings.json | python3 -c "import sys,json; d=json.load(sys.stdin); print('\n'.join(d.get('mcpServers',{}).keys()))" 2>/dev/null || echo "(无法读取 MCP 列表)"
```

### 检查 CLI 工具

对 Phase 2 列出的每个 CLI 候选，执行：

```bash
command -v <tool_name> && echo "已安装" || echo "未安装"
```

将结果整理为表格：

| 工具 | 类型 | 本地状态 | 决策 |
|---|---|---|---|
| brave-search | MCP | 已注册 | 直接使用 |
| firecrawl | CLI | 未安装 | 待确认安装 |
| ... | ... | ... | ... |

---

## Phase 4：缺口处理（半自动，需用户确认）

对本地缺失的工具，**不自动安装**，而是生成安装清单展示给用户：

```
以下工具本地未找到，建议安装：

1. [工具名] — [用途说明]
   安装命令：<具体命令>
   是否需要 API Key：是 / 否
   参考：<来源或文档>

是否执行安装？可回复"全部安装"、"只装第 1 项"或"跳过"。
```

用户确认后，逐项执行。遇到需要 API Key 或 OAuth 的工具，暂停并提示用户手动完成配置步骤。

---

## Phase 5：skills.sh 检索

用关键词搜索 skills.sh，关键词来自任务的核心动词和领域词：

```bash
npx skills find "<关键词1> <关键词2>"
```

对返回结果：
- 列出名称、来源仓库、简介
- 标注与当前任务的相关度（高 / 中 / 低）
- 高相关的询问用户是否安装：

```
找到以下相关 skill：

- [skill名] (来源: owner/repo) — [功能描述]
  相关度：高，因为它覆盖了 [具体能力]

是否安装？
```

用户确认后执行：

```bash
npx skills add <owner/repo> --skill <skill-name>
```

---

## Phase 6：输出框架

整合所有决策，输出结构化的任务执行框架：

```markdown
## 任务框架：[任务名称]

### 工具链
| 能力维度 | 选用工具 | 类型 | 状态 |
|---|---|---|---|
| 网络搜索 | brave-search MCP | MCP | 已就绪 |
| 网页抓取 | firecrawl | CLI | 已安装 |
| ... | ... | ... | ... |

### 已安装 Skills
- [skill名]：[用途]

### 执行路径
1. [步骤1]
2. [步骤2]
...

### 注意事项
- [需要 API Key 的工具及配置入口]
- [已知限制]
```

同时将上述内容写入当前目录的 `.task-manifest.md`，供后续对话引用。

---

## 注意事项

- 安装工具前**必须等待用户确认**，不自动执行破坏性操作
- 若工具需要 API Key，仅提供配置说明，不代替用户填写凭证
- 若 `npx skills find` 无结果，直接跳过 Phase 5，不报错
- 同一能力有多个工具时，优先推荐安装量更高、维护更活跃的
