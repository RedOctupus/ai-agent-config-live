# 项目协作契约文档 — 输出模板

生成文档必须包含以下章节。结合用户提供的实际项目上下文填写；不确定处标注「待确认」。

---

# 1. 项目基本信息

- 项目目标
- 核心功能范围
- 技术栈
- 团队成员与角色（如果已提供）

# 2. 模块拆分与负责人

- 按业务边界拆分模块
- 每个模块的职责范围
- 每个模块明确「不负责什么」
- 模块负责人或建议负责人
- 模块之间的依赖关系

# 3. 目录与代码边界契约

- 推荐的项目目录结构
- 每个模块允许修改的目录
- 公共目录、入口文件、全局配置、路由、数据库结构等由谁维护
- 哪些文件不能多人随意同时修改

# 4. 接口契约

对每个跨模块接口明确：

- 接口名称和用途
- 请求地址与请求方式
- 请求参数、类型、是否必填、示例
- 返回结果、字段类型、字段说明、示例
- 错误码和异常返回格式
- 分页、排序、筛选等通用规则
- 接口未完成时，前端或调用方如何使用模拟数据继续开发

# 5. 数据契约

- 核心数据表或核心数据模型
- 字段名称、类型、是否必填、含义
- 字段命名规则
- 状态字段、时间字段、删除规则
- 数据库变更如何提交和同步

# 6. 前后端协作契约

- 接口文档维护位置和更新责任人
- 模拟数据规范
- 页面、组件、接口联调的流程
- 接口变更时的通知和兼容规则

# 7. 公共规范

- 命名规范
- 代码格式规范
- 环境变量规范
- 配置文件规范
- 日志和错误处理规范
- 提交代码信息的写法

# 8. Git 协作契约

- 分支命名规则
- 功能开发、测试、发布分支的用途
- 提交与合并流程
- 合并前必须完成的检查
- 出现冲突时的处理原则
- 禁止直接修改或覆盖他人成果的规则

# 9. 联调、测试与验收契约

- 每个模块交付前必须满足的条件
- 自测清单
- 联调流程
- 验收标准
- 已知问题的记录方式

# 10. 变更管理

- 哪些改动必须先讨论
- 接口、数据表、公共配置变更的申请与通知方式
- 紧急变更的处理流程
- 契约文档的版本记录格式
