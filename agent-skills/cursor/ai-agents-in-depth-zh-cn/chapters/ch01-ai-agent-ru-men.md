# Chapter 1: AI Agent 入门

## Core Idea
AI Agent 不是“你问一句、它答一句”的被动对话系统，而是能够自主规划执行步骤、调用工具、根据反馈不断调整策略的智能系统。其本质可概括为 **Agent = LLM（大脑）+ 上下文（眼睛）+ 工具（手脚）** 三个组件的协同。

## Frameworks Introduced

- **Agent = LLM + 上下文 + 工具**：Agent 系统的核心公式。LLM 负责理解、规划与决策；上下文提供当前决策所需的全部信息；工具将决策转化为对外部世界的改变。
- **Agent = 大脑 + 眼睛 + 手脚**：更直观的类比。大脑（LLM）做决策；眼睛（上下文）看世界；手脚（工具）执行动作。
- **LLM 作为决策内核**：不只是一组参数，而是“理解意图 → 拆解任务 → 持续判断 → 调用工具 → 调整策略”的完整闭环。其能力来自预训练（世界知识 + 语言能力）与后训练（决策策略）。
- **上下文作为观察空间**：Agent 在每个决策点能看到的全部信息，包括环境信息、用户记忆、领域知识、自身状态、任务进展。
- **工具作为动作空间**：从预定义 API 到按需加载的 Skills、动态生成的代码、子 Agent 协作、事件触发、用户沟通等广义能力集合。
- **五类工具分类**：
  - 感知工具：搜索、文件系统、数据库、API
  - 执行工具：代码执行、文件操作、系统命令、外部 API 调用
  - 协作工具：子 Agent、人类确认、多 Agent 协调
  - 事件触发工具：邮件、Webhook、定时任务
  - 用户沟通工具：消息、语音、邮件
- **工具调用（Tool Calling / Function Calling）**：现代 LLM Agent 的核心能力。流程分四步：声明工具 → 模型决定调用 → 执行结果回写上下文 → 模型决定下一步。
- **ReAct 循环**：思考（Thought）+ 行动（Action）+ 观察（Observation）的迭代循环，是 Agent 自主执行的基础模式。
- **Harness 工程**：模型能力之外的工程竞争力，包括 Loop 工程、工具设计、护栏、编排、模型选择等。

## Key Concepts

- **LLM（Large Language Model）**：Agent 的大脑，负责理解、规划、推理、决策。
- **上下文（Context）**：Agent 在决策时能看到的一切信息。
- **工具（Tools）**：Agent 与外部世界交互的桥梁。
- **工具调用（Tool Calling）**：LLM 通过结构化方式调用外部工具的机制。
- **零样本泛化（Zero-shot Generalization）**：LLM Agent 即使面对未见过任务，也能组合已有知识直接处理。
- **ReAct**：Reasoning + Acting 的循环范式。
- **Harness 工程**：围绕模型能力做工程封装、编排、护栏与优化，以释放模型潜力。
- **编排模式**：工作流（Workflow）与自主（Autonomous）之间的连续光谱。

## Mental Models

- **Use Agent 当任务需要多步骤自主执行时**：不是一次性问答，而是持续迭代、调用工具、验证结果。
- **Think of 工具 as 动作空间**：工具的种类、粒度、定义质量直接决定 Agent 能走多远。
- **Think of 上下文 as 可观察状态**：上下文窗口是 Agent 当下能看到的“世界”，上下文工程决定 Agent 能看到什么、看不到什么。
- **Prefer 通用工具 over 专用工具**：通用工具让 Agent 通过组合创造性地解决问题；专用工具过多会限制灵活性。
- **Balance 自主性与可控性**：完全自主适合探索性任务；严格工作流适合安全关键或合规场景。

## Anti-patterns

- **工具接口定义不清晰**：模型会乱用工具、传错参数。
- **错误处理不到位**：工具一旦失败，Agent 陷入死锁或无限重试。
- **工具权限过于宽泛**：Agent 出错时造成难以挽回的后果。
- **过度依赖后训练而忽视 Harness 工程**：模型能力只是基础，工程封装才是产品竞争力的关键。
- **把 Agent 当作单次问答系统**：忽视其自主规划、迭代执行的本质。

## Code Examples

```json
// 工具调用四步流程：以查天气为例
// 第一步：声明工具
[
  { "name": "get_weather", "parameters": { "city": "string" } }
]

// 第二步：模型决定调用
{
  "tool_calls": [{
    "function": "get_weather",
    "arguments": { "city": "北京" }
  }]
}

// 第三步：结果追加到上下文
{
  "tool_call_id": "call_1",
  "content": "{\"temp\":28,\"sky\":\"晴\"}"
}

// 第四步：模型基于结果回复
{
  "content": "北京今天 28°C，晴。"
}
```
- **What it demonstrates**：工具调用是 Agent 将内部决策转化为外部行动的核心机制，模型自主决定“要不要调用、调哪个、传什么参数”。

## Worked Example

**场景：Cursor 编写代码的 Agent 工作流**

需求文档 → 搜索相关代码 → 编辑多个文件 → 运行测试 → 调试修复 → 直到通过。这个过程中，Cursor 作为 Coding Agent 使用：
- **眼睛**：代码库、需求文档、终端环境、测试输出
- **手脚**：文件读写、命令执行、搜索工具、代码编辑
- **大脑**：LLM 规划修改步骤、判断错误原因、决定下一步

这展示了 Agent 不是“回答一个问题”，而是“完成一个目标”——自主迭代直到任务完成。

## Key Takeaways

1. **Agent 的三元公式**：LLM + 上下文 + 工具。三者缺一不可，分别对应决策、观察、行动。
2. **工具设计是工程核心**：接口清晰、错误处理完善、权限最小化，才能让 Agent 安全有效地行动。
3. **上下文决定能力上限**：Agent 能做什么，很大程度上取决于它能看到什么信息。
4. **Harness 工程是竞争力**：同样的模型，通过更好的工程封装、编排、护栏、缓存、评估，可以产生完全不同的产品体验。
5. **从被动对话到自主执行**：Agent 的本质是“完成目标”，而不是“回答问题”。
