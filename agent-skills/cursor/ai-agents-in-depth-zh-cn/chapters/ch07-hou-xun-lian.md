# Chapter 7: 模型后训练

## Core Idea
Agent 的大脑（LLM）的能力分三个阶段炼成：预训练（读万卷书）→ SFT（老师示范）→ RL（实战试错）。本章聚焦如何通过 **后训练（SFT 与 RL）** 让模型更好地利用上下文和工具。核心认知：**SFT 记忆，RL 泛化**；**数据和环境比算法更重要**。

## Frameworks Introduced

- **模型能力三阶段炼成**：
  1. **预训练（Pre-training）**：海量互联网文本上做“预测下一个词”，学会语言规律、世界知识、基本推理。代价最高，是能力地基。
  2. **监督微调（SFT）**：用几千～几万条“输入—输出”示范对训练模型，学会指令遵循、输出格式、风格流程。代价低、稳定，是当前部署模型的标配。
  3. **强化学习（RL）**：让模型在任务环境中反复尝试，根据奖励信号优化策略。无标准答案，学会可迁移的决策策略。代价高，但泛化能力更强。
- **SFT 记忆，RL 泛化**：SFT 倾向于记住训练数据中的答案；RL 倾向于学会一套可迁移的策略，面对没见过的情况更稳。
- **数据和环境比算法更重要**：RL 算法（PPO、GRPO 等）知道怎么用就够了，真正决定成败的是仿真环境和训练数据质量。
- **很多时候 SFT 数据到位就不需要 RL**：不是所有问题都需要 RL，高质量 SFT 数据能解决大量场景。
- **何时选 SFT，何时选 RL**：
  - SFT：需要稳定遵循固定格式、流程、风格；有明确示范数据；任务边界清晰。
  - RL：需要决策、探索、面对开放环境；有明确奖励信号；需要泛化到新情况。
- **SFT 与预训练在数学上是同一任务**：都是预测下一个词，差别只在数据。
- **RL 的奖励信号来源**：环境结果、LLM-as-a-Judge、人类偏好、规则验证器。
- **仿真环境是 RL 的练习场**：真实、可控、可扩展的仿真环境是 RL 成功的关键。
- **模型选择决策框架**：在当前模型上评估，建立基准；新模型发布后在自有评估集上测试；用统计显著性判断是否切换。
- **提示词工程 vs 微调（SFT/RL）的边界**：能用清晰 prompt + 上下文工程解决的，不要微调；需要模型改变决策策略或深度内化领域知识时，才考虑微调。

## Key Concepts

- **Pre-training**：预训练，基于海量文本预测下一个词。
- **SFT（Supervised Fine-Tuning）**：监督微调，用示范数据训练模型。
- **RL（Reinforcement Learning）**：强化学习，根据奖励信号优化策略。
- **NTP（Next Token Prediction）**：预测下一个词，是预训练和 SFT 的基础任务。
- **PPO / GRPO**：常用的 RL 算法。
- **Reward Function**：奖励函数，定义行为好坏。
- **Policy / Value Model**：策略模型和价值模型，RL 中的核心概念。
- **Generalization**：泛化能力，面对未见过情况的表现。
- **Memorization**：记忆能力，对训练数据的拟合。
- **Simulation Environment**：仿真环境，用于 RL 训练的可控真实场景。
- **Preference Data**：偏好数据，人类或模型对输出的好坏排序。
- **Prompt Engineering vs Fine-tuning**：提示词工程与微调的边界选择。
- **Regression**：模型升级后某些任务性能退化。

## Mental Models

- **Pre-training = 读万卷书**：积累语言和世界知识，但还不会好好回答问题。
- **SFT = 老师手把手教标准解法**：模仿示范，学会对话协议和输出格式。
- **RL = 自己下场做题、根据对错反复打磨**：试错中学习可迁移策略。
- **SFT is for format and protocol, RL is for strategy and exploration**：SFT 解决“怎么回答”，RL 解决“怎么决策”。
- **Data quality > algorithm novelty**：干净、对齐、覆盖边界的数据比调算法更重要。
- **Environment fidelity > reward hacking**：仿真环境不真实，模型会学会钻奖励函数空子。
- **Start with SFT, escalate to RL**：先用 SFT 建立基线，只有需要泛化和探索时才上 RL。

## Anti-patterns

- **一上来就用 RL**：很多场景 SFT 就够了，RL 成本高、不稳定。
- **忽视数据质量**：垃圾数据导致模型学到错误模式。
- **奖励函数设计不当**：奖励信号不能真实反映任务成功，导致奖励钻洞（reward hacking）。
- **用 RL 解决格式问题**：格式、风格问题用 SFT 更稳定。
- **不做模型替换实验**：不知道瓶颈在模型还是 Harness，就盲目微调。
- **忽视仿真环境建设**：RL 没有高质量仿真环境就是空中楼阁。
- **微调后不做回归测试**：新能力学到了，旧能力可能遗忘了。

## Worked Example

**场景：退款客服 Agent 的模型后训练决策**

问题：Agent 有时在退款政策边缘 case 上处理不稳定。

1. **先用 SFT 收集示范数据**：整理 500 条边界 case 的标准处理轨迹（含思考过程、工具调用、回复），训练模型遵循标准流程。
2. **评估**：发现 SFT 后稳定 case 处理好了，但没见过的新边界 still 容易错。
3. **引入 RL**：在仿真环境中让模型处理各种退款场景，奖励函数 = 结果正确（退款/拒绝正确） + 过程合规（查询订单、遵循政策） + 回复质量（完整、礼貌）。
4. **验证**：在自有评估集上测试，比较 SFT 与 RL 版本，确认 RL 在未见 case 上表现更好且无显著 regression。

这个例子展示了 SFT 与 RL 的递进关系：SFT 建立基线，RL 解决泛化。

## Key Takeaways

1. **模型能力三阶段**：预训练 → SFT → RL，缺一不可，按顺序递进。
2. **SFT 记忆，RL 泛化**：SFT 让模型学会格式和示范；RL 让模型学会可迁移决策策略。
3. **数据和环境比算法更重要**：好数据 + 真实仿真环境胜过花哨算法。
4. **SFT 能解决大部分工程问题**：不要上来就用 RL，先把 SFT 数据做好。
5. **RL 适用于开放决策和探索**：需要模型自己试错、面对未知情况时，RL 更有价值。
6. **提示词工程 vs 微调有明确边界**：能用上下文工程解决的，不要微调；需要改变决策策略时，才考虑 SFT/RL。
7. **评估和回归测试是后训练不可分离的部分**：没有评估就不知道学到了什么、丢了什么。
