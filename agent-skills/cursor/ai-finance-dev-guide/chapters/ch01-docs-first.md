# Chapter 1: 先看文档再开始

## Core Idea
智能财富管家以自然语言 + 多 Agent + RAG/NL2SQL/NL2API 支撑六类业务场景；开工前对齐文档优先级，统一五 Agent 口径（customer/advisor/risk/analyst/operator），并按 `必修/建议/选修` 标记裁剪范围。

## Frameworks Introduced
- **文档冲突优先级**: 范围与需求以《需求文档-修改版》为准；本指南只补流程与工程方法，不扩缩需求；偏离须 ADR 裁决。
- **五 Agent 统一口径**: 需求写「四大 Agent」、设计与本指南按五个执行；客户画像是投顾前置能力，非独立 Agent。
- **指南使用五问**: 为什么要做、谁负责、产出什么、如何验证、未通过能否进入下一阶段。

## Key Concepts
- **RAG**: 先检索知识再生成，降低幻觉
- **NL2SQL / NL2API**: 自然语言查数 / 调业务接口（经权限与风控）
- **六类场景 ≠ 六个 Agent**: 场景与 Agent 映射需能说清

## Reference Tables
| 标记 | 含义 |
|------|------|
| `必修` | 五周内必须做到 |
| `建议` | 理解框架或简化版 |
| `选修` | 企业扩展，教学可跳过 |

## Worked Example
**文档读序**: 需求最终版 → 功能设计 → 记忆架构 → 开发引导 → 答辩须知 → 本指南；修改痕迹版仅追溯，不作开发依据。

## Key Takeaways
1. 编码前读完必读清单，冲突按需求最终版裁决
2. 团队人数 3–7 人时合并角色，但五 Agent 归属须清晰到人
3. 时间紧只跑 `必修` 章节仍可保住答辩基本盘
