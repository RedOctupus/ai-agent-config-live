# Chapter 2: 企业级 AI 项目开发总流程

## Core Idea
流程价值在于每阶段有**最低交付物 + 通过条件 + 门禁**；AI 项目在阶段 7 必须过效果指标门槛，运行阶段产出须回流需求形成迭代。

## Frameworks Introduced
- **九阶段主链路**: 立项→需求→MVP→设计→分工→开发→测试与AI评测→发布→运行迭代。
- **三道关键门禁**: 需求可开发可测试；功能与 AI 指标达标；可部署、可观测、可回滚。未通过则回退补产出，非硬往下走。
- **九阶段 ↔ P0–P5 映射**: P0=立项+需求+MVP+设计分工准备；P1–P4=开发实施；P4–P5=测试评测；P5=发布答辩复盘。

## Mental Models
- Use 门禁回退箭头 when 集成阶段才发现需求歧义 — 应回到 S2 而非加班硬补
- Think of 阶段 7 as AI 与传统项目的最大分岔 — 验收标准须在阶段 2 写死

## Anti-patterns
- **文档越多越好**: 无检查门槛的文档堆叠
- **断掉虚线回流**: 线上问题不进需求与评测集

## Key Takeaways
1. 表格最后一列「通过条件」是各阶段 DoD 的父级
2. MVP 与方案评审通过后再大规模并行开发
3. 教学项目评审可由老师/组长承担，机制不变
