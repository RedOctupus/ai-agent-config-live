# Mock 数据协作规范 — 输出模板

结合用户提供的实际上下文填写；不确定处标注「待确认」。

---

# 1. 当前依赖与并行开发分析

- 当前要完成的功能
- 依赖哪些未完成的模块、接口或数据
- 哪些依赖适合使用 Mock 数据并行开发
- 哪些依赖不适合使用 Mock 数据，以及原因
- 可能影响的前端、后端或其他模块

# 2. 数据契约

针对每个需要 Mock 的接口或数据模型：

| 字段名 | 类型 | 是否必填 | 字段含义 | 允许的值或格式 | 示例 |
| --- | --- | --- | --- | --- | --- |

同时明确：

- 请求参数
- 返回数据外层结构
- 分页、排序、筛选规则
- 空值、缺失值的处理规则
- 错误码和错误返回格式
- 契约版本号

# 3. Mock 数据设计

针对每个接口或数据模型：

- Mock 名称和用途
- 对应的真实接口或真实数据来源
- Mock 文件建议位置
- 建议使用的服务层或接口层名称
- 至少一组正常数据示例
- 空数据示例
- 异常或错误示例
- 分页、边界值或特殊状态示例

# 4. 代码边界与接入方式

| 内容 | 约定 |
| --- | --- |
| Mock 文件存放位置 | 明确建议目录 |
| 业务页面调用方式 | 必须通过哪个服务或接口层 |
| 禁止修改的位置 | 例如页面中直接硬编码数据 |
| 真实接口完成后的替换位置 | 明确到服务层或配置层 |
| 负责人 | 未提供则标注待确认 |

并给出推荐的目录结构和最小代码示例，说明如何做到「开发时使用 Mock、联调时切换真实接口」，同时尽量不修改业务页面。

- 清理或隔离方式：

# 6. Mock 与真实数据一致性校验

- 需要逐项核对的字段
- 类型、空值、枚举、时间格式、分页和错误结构的校验方法
- 出现不一致时的处理优先级：先检查并修正契约，再统一调整实现；禁止在页面内临时偷偷兼容
- 联调前、联调中、发布前分别需要执行的检查

# 7. 测试与验收清单

- Mock 场景测试清单
- 真实接口联调清单
- Mock 与真实接口切换后的回归测试清单
- 发布前确认 Mock 已关闭、隔离或清理的检查项

# 8. 风险与后续收敛建议

- 可能出现的 Mock 与真实数据不一致风险
- 如何防止 Mock 长期遗留在生产代码中
- 哪些 Mock 需要在什么阶段删除
- 建议由谁负责最终统一收敛
