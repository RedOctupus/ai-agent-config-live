# 团队协作与多模块维护（按需读）

不拷进业务项目。项目有多个维护者 / 多个模块、或有跨模块共享层（DB / 认证 / 接口）时才读。单人单模块项目不用这套，直接按单人流程走。

## 目录结构（按模块拆，不按人）

```text
docs/memory/
├── MEMORY.md       # 根索引：项目一句话 + 各模块静态指针（负责人 + 子目录）；用 templates/ROOT-MEMORY.md
├── OWNERS.md       # 模块 → 负责人 认领表（权威，用 templates/OWNERS.md）
├── ENVIRONMENT.md  # 服务对象大环境 —— 项目级一份，全模块共享
├── TODO.md         # 项目级待办（跨模块 / 里程碑）
├── ITERATION.md    # 项目级变更史 —— 追加型，人人可写，merge=union
├── HANDOVER.md     # 跨阶段必知事实 —— 项目级一份，**行内改（非追加），禁止 union merge**
├── GLOBAL/         # 共享层（DB/认证/API 约定）→ 架构负责人单一 owner + 版本号
│   └── FRAMEWORK.md
└── <模块>/         # 各模块 mini memory 包（见下）
    ├── MEMORY.md       # 模块一句话快照 + 门闸（依赖 GLOBAL vN）
    ├── REQUIREMENTS.md # 模块需求条目
    ├── FRAMEWORK.md    # 模块内选型 / 分层
    ├── FLOW.md         # 模块内端到端流程
    ├── TODO.md         # 模块待办
    └── tests/
```

每个模块一个子目录，复用同一套模板，就是一份缩小版 memory。**按模块拆，不按人拆**：人会流动，模块边界才稳定清晰。

**各源文件怎么排（能共享的放根一份，模块独有的放子目录）：**

| 源文件 | 放哪 | 原因 |
| --- | --- | --- |
| `ENVIRONMENT.md` | 根（一份） | 服务对象对所有模块一样，不存在「每模块一个大环境」 |
| `FRAMEWORK.md` | `GLOBAL/`（跨模块）+ 各模块 | 跨模块选型（DB/认证/API）进 GLOBAL；模块内选型/分层进模块目录 |
| `FLOW.md` | 各模块 | 模块内端到端流程进模块目录；跨模块链路极少，记根 MEMORY 一句话 |
| `REQUIREMENTS.md` | 各模块 | 需求天然按模块拆；跨模块需求极少，记根 MEMORY 一句话 |
| `TODO.md` | 根（项目级）+ 各模块 | 项目级待办根一份；模块待办模块目录一份 |
| `ITERATION.md` | 根（项目级，追加型） | 追加一行 union merge 不冲突；模块级变更进模块 tests / 模块内记录 |
| `HANDOVER.md` | 根（一份）+ 模块可选 | 必知事实的典型内容（环境 / 路径 / 账号位置 / 工具版本）对所有模块一样，同 `ENVIRONMENT.md` 的处理；模块独有的结论 / 坑可在模块目录再放一份 |
| `MEMORY.md` | 根（索引）+ 各模块（mini 快照） | 根=静态指针（负责人+子目录）；模块目录=各模块自己的快照（一句话/进度） |

## 三层所有权（冲突面归零）

| 层 | 谁 owns | 冲突 |
| --- | --- | --- |
| 模块子目录 | 该模块负责人，别人只读 | 模块内单人 = 不撞 |
| `GLOBAL/` | 架构/技术负责人 | 单一 owner = 不撞 |
| 根 `MEMORY.md` + `OWNERS.md` | 架构负责人维护（增删模块时才改） | 单一低频 = 不撞 |
| `ITERATION.md` / `tests/` | 人人追加 / 一人一文件 | 追加+命名空间 = 不撞 |

## 两条硬规则

1. **大记忆不可动，但记录负责人**：根 `MEMORY.md` + `GLOBAL/`（共享层）只有**架构负责人**可改；模块 owner 与各模块 Agent **只读、禁止修改**。模块 Agent 只写自己模块子目录，跨模块的事只提不写。根 `MEMORY.md` 只放**静态指针**（模块 → 负责人 → 子目录），**不放模块的「当前一句话」**——那句话在各模块自己的 `MEMORY.md`；根指针只在**增删模块**时由架构负责人改，与 `OWNERS.md` 认领表一致。
2. **模块命名 + owner 认领 = human-in-the-loop，候选不乱编**：新增模块 / 建子目录 / 认领负责人时，Agent **只提候选**，且候选**必须依据项目记忆**（谁在负责该模块、FRAMEWORK / ITERATION 里已有谁），**禁止自行编造人名 / 模块名**。记忆里没有 → 请求用户自己填写；用户不填 → 默认占位「mini memory」，不编一个像真的名字。最终由**人类负责人拍板确认**后才落盘。与「技术选型硬阀门」同款：先候选、等确认、再写。

## 共享层变更协议（唯一破例点）

`GLOBAL/` 是所有人共同依赖的，各自改会静默分叉。走混合协议：

| 改动 | 流程 |
| --- | --- |
| 破坏性（加列 / 改认证 / 改接口） | 提 PR → owner 评审拍板 → 更新 `GLOBAL/` + 升版本号 → **通知所有模块 owner** 重核依赖 |
| 小改动（补文档 / 修措辞） | owner 直接改 + 升版本号 + 通知 |

模块侧引用「依赖 GLOBAL vN」，**不写「依赖最新的会变的东西」**——版本一升，依赖方被点名重核。

## merge 策略

- 模块内：owner 自己 rebase，单人无冲突
- 根索引 / 共享层：PR + owner 拍板（不靠 git 硬解）
- 根索引只放静态指针，**不放各模块「当前一句话」**：git 按 hunk（带上下文）合并，多人改**同一文件里紧邻的行**照样冲突（沙盒实测「一行一模块」紧邻表格行会撞）。活状态回模块子目录，根索引只在增删模块时由架构负责人改。
- `ITERATION.md`：追加一行不改历史；`.gitattributes` 标 union 自动合并：

```text
docs/memory/ITERATION.md merge=union
```

- `HANDOVER.md`：**行内改**文件，**不得**套用上面的 union —— union 会把旧值和新值都留在文件里，而「改一条事实」的语义必须人工取舍。规则：改前先 pull，冲突人工解；改完追加一行 `ITERATION.md` 留痕（多 Agent 同机未提交时，那行是唯一线索）
- `tests/`：文件名带日期+任务，不同人不同文件，物理不冲突

## 两拨「文件」别混

「传到成员手中」是两样东西：

1. **kit（工具/说明书）**：`SKILL.md` + `templates/` + `references/` + `scripts/`，教 AI「怎么建记忆」的通用模板。**每人机器装一份**：源放共享仓库 + 版本号 → 成员 pull → 各自同步本机 `.cursor/skills/` + `.claude/skills/`。类比：螺丝刀，每人工具箱一把。
2. **docs/memory（项目记忆）**：`MEMORY/FRAMEWORK/FLOW…`，长在**每个项目仓库里**，靠 pull/push 共享**一份**，不是每人一份再合并。类比：设计图纸，团队共享一份。
