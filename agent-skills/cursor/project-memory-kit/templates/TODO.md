## 结构约定（照这四条写，四个毛病就不会长出来）

1. **父项只当分组名。** 父项文字里**禁止写「当前状态」**（「只做到留痕、行为不变」这类）——它必然过期，因为没人会在改子项时回头改父项。**父项勾选 = 子项全绿。**
2. **不在正文里计数。** **不要写「下面 N 项」**——这个数字必然过期，而没人会回头改。**重复的直接合并**，不要留一条写「与上一条合并处置」，那是书签不是待办。
3. **已知限制不留在这里。** 判据不是「有没有动作」，而是「**能不能给出验收**」：补得出量法（命令 / 可观察量）→ **留在 TODO 并写上验收**；补不出 → 才归 `HANDOVER.md` §6 坑 / §7 已排除。先试着一两句话给出量法，给不出再搬——否则 HANDOVER 会变成愿望垃圾桶，而它**没有外移退路**。
4. **阻塞要可见。** 同一动作解锁多条时，**只留一条阻塞项**，被它挡住的多条统一标 `⛔ 等 <那条的短名>`。同一动作若有几条不同理由，**并列在那一条阻塞项下面**，不要写成两条阻塞项（那会看起来像两件事）。否则「重启一次解锁多条」这个事实看不出来，你会当成好几件独立的事。
