# Kit × AOCI 工作区隔离与宿主验收计划（先于实现）

日期：2026-10-06。只在本实验目录建测试工作区；原 SSSS、用户已有检出目录及全局 Kit 安装不作为测试写入对象。用户确认：工作区而非人员/模块是 AOCI 隔离单位；新人先提示、写源码前检查，不静默创建；个人图不直接文本合并；合并后以真实源码由集成 Agent 更新全局图；候选 RED→GREEN 后才改 Kit 两份权威副本。单人 clone 已是可用工作区，不强制选择或创建 worktree；AOCI 仍是项目级自愿启用。

## 模型与边界

- 工作区 = 有独立绝对根路径的 Git clone 或 worktree。同一人可拥有多个工作区，同一模块可被多个工作区改；Kit 的模块 OWNER 与工作区不是同一维度。
- 单人默认 Kit-only；用户启用 AOCI 后，当前 clone 可直接按项目级 MCP 使用。多人模式的集成分支检出目录不可直接写源码；功能分支 clone/worktree 可写。仅凭 Git 无法证明没有别的 Agent 同时写同一目录，必须显式提示该限制。
- 个人工作区在自己的源码版本上维护 AOCI 地图。合并请求可携带地图差异供审查，但全局图只能由集成工作区对**合并后的源码**重新签发候选并更新；旧工作区的 batch/candidate/SHA 不能直接重放。发生同对象冲突、范围/字典变更、证据不足或 AOCI 治理不对齐时停止自动集成。
- Kit 仅保存启用状态、工作区准入与阶段性交接；AOCI 的规则/命令/索引格式由当前 AOCI Guide 与 MCP 自己负责。升级 Kit 不重建 AOCI；升级 AOCI 不要求改 Kit，除非能力契约不再满足。

## TDD 用例（先 RED）

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| W01 | 单人项目、新 clone 已在 Git 分支 | 可直接工作；不强制回答工作区问题或创建第二个 worktree；AOCI 未启用时明示 Kit-only。 |
| W02 | 多人项目 clone 位于集成分支 | 入口提醒创建/切换独立工作区；不静默创建，不把 owner 当工作区。 |
| W03 | 功能分支 clone / linked worktree | 识别为独立工作区；不重复创建。 |
| W04 | 显式创建 | 必须提供目标绝对路径、分支和基线；已存在目标或分支、不合法路径、脏基线等失败关闭；只在实验目录实际创建。 |
| W05 | 两个并行工作区 | 两者的 `--repo`、宿主 MCP 绝对路径和 AOCI 运行状态彼此隔离；不共享 `.aoci` 事务或项目配置。 |
| W06 | 合并源代码与个人图 | 个人图仅作提案；先集成代码，再以最新源码签发全局图候选；全局 Verify/Check/Guide 均对齐才放行。 |
| W07 | 同对象/过期/治理冲突 | 不直接拼接 Entry、不复用旧 batch；停在人工裁决。 |
| W08 | Kit/AOCI 解耦更新 | Kit 不内嵌 AOCI 命令状态机；AOCI 版本变动通过能力/工具校验，不自动覆盖本机配置或升级二进制。 |
| W09 | 三宿主真实会话 | Codex、Claude Code、Cursor Agent 各自在**独立实验工作区**真正发现 MCP、读取规则/Overview、给出源码核对及真实认知状态；不能拿配置存在、协议探针或模拟器代替。 |
| W10 | 权威副本与原项目 | 两份 Kit 权威副本逐字一致，原 SSSS 清单/哈希/Git 状态不变；报告所有未通过项。 |

## 执行顺序与停点

1. 写可执行契约/工作区测试并存 RED；不因测试难跑就修改预期。
2. 在 `kit-candidate/` 与本实验目录实现最小能力，跑 GREEN；先实测 AOCI 对 worktree 根路径/基线是否兼容，不假定能直接复制正式地图。
3. 使用受信任的沙盒及隔离工作区做三宿主真实会话；安装 Cursor 官方 CLI 仅限用户已授权的本机用户目录。登录/权限/工具截断或 MCP 不可用时如实停下，不伪造 PASS。
4. 只有候选测试通过且宿主兼容边界写清，才同步到两份 Kit 权威副本。修改后执行技能验证、目录字节一致、记忆同步与原项目不变检查；不自动 push，也不覆盖本机已装技能。
