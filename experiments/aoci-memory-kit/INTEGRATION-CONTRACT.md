# 候选集成契约（未部署）

## 权威归属

| 问题 | 首要依据 | 外挂的作用 |
| --- | --- | --- |
| 为什么做、验收什么、哪些技术已获同意 | Kit 的 `REQUIREMENTS` / `FRAMEWORK` / `FLOW` / `MEMORY` | AOCI 不得把“代码里出现了某库”提升为用户已确认选型 |
| 当前文件负责什么、要连同哪些文件看、接口与非显然约束 | 当前源码/测试；AOCI F/R/A/S 是可检索导航 | AOCI 条目必须源绑定，不能作为源码的替代证据 |
| 哪次交付通过、还有什么风险 | Kit 的 VERIFY / HANDOVER / ITERATION | 不把战报复制进 AOCI 的每文件条目 |
| 两者冲突或 AOCI stale | 当前源码、测试、用户确认的设计决定 | 停用冲突条目，报告漂移；不让过时地图覆盖已确认约束 |

## 读取流程（待试验）

1. 先按项目原规则读 Kit 的 `MEMORY.md`。纯需求、业务、文档任务保持 Kit 原流程。
2. **只有启用 AOCI 的代码会话**：遵守运行中 AOCI 版本的规则，读取完整 Overview 和身份/对齐状态；再按任务读取少量源码/测试核实。不能用一次 `aoci_search` 冒充完整 Overview。若完整首读成本不可接受，就不启用该模式，而不是静默跳过协议。
3. 代码变更经测试稳定后，分别更新受影响的 Kit 槽位和 AOCI 条目；AOCI 的维护只走官方 MCP/Guide，不写第二套自制状态机。
4. AOCI 不可用、未对齐或模型上下文已压缩而未重新交付 Overview 时，退回 Kit＋源码直接核对；不得引用过时条目作“已验证”。

## 初始化/维护边界

- `aoci init` 只在**沙盒 Git 仓**运行。事先保存 `AGENTS.md`、`.gitignore` 和宿主配置的快照；逐行审查 AOCI 增加的规则，不覆盖 Kit 的技术选型、人审及记忆写入规则。
- AOCI 的索引文件需随沙盒 Git 跟踪；宿主配置含本机绝对路径，留沙盒本地并忽略，不推广到双机共享模板。
- 首轮只做代码索引，不接 SSSS 的 MySQL/Milvus/Neo4j，也不读取 `.env`。这次评估的是**编码 Agent 的代码地图**，不是 SSSS 业务 Agent 的长期记忆。
- 任何正式 Kit 模板改动、目标项目改动、安装/注册 MCP、提交或推送，都应另有明确开工决定；本草案不授权这些动作。
