# Cursor 用户全局规则（可复用资产）

以机主 Cursor 账号的 User Rules 快照为基线维护的规则文档，包含用户授权的仓内修订。其他 Agent 读这里借鉴写法。本配置仓干活时不注入这份规则。

## 文件

| 中文职责 | 路径 |
| --- | --- |
| 规则全文（仓内维护版） | `RULES.md` |
| 可直接复制到 User Rules 的语义标记文本 | `RULES.txt` |
| 借鉴方式与维护约定 | `README.md`（本文件） |

## 其他 Agent 怎么借鉴

1. 先读 `RULES.md`。按目标项目取需要的条目。
2. 人类明确说在某个项目启用时，才把选中的条目写进那个项目自己的规则，或那个账号的 User Rules。
3. 人类点名要整份启用时，才把全文放进目标项目的规则。默认整份只作参考。
4. 在本配置仓干活的 Agent 以 `.cursor/rules/project-memory.mdc` 和根 `AGENTS.md` 为准。

## 怎么维护

- 账号里的 User Rules 变了：人说明变更后，核对仓内修订再更新 `RULES.md`，记录账号基线日期。
- 用户只要求改仓内文档时：更新文档修订日期，并标明是否已写回账号；不把仓内修订日期当成账号快照日期。
- `RULES.md` 是维护源；正文变更时同步更新 `RULES.txt`。TXT 只放可执行正文，按优先级、触发条件、适用范围和输出时机分块，不带维护元信息。
- 本目录改了，不会回写 Cursor Settings。账号里改了，也不会自动改本目录。
- 不放 API key、token。当前快照没有密钥。
- `scaffold/scripts/sync-skills.sh` 与 `restore.sh` 不碰本目录。更新靠人点名后改文件再提交。
