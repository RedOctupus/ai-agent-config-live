# Code Example Skill

生成完整、可直接运行的代码示例，附带 Markdown 分段注释。不留 TODO，不留骨架——用户拿到即可运行，看注释即可理解。

---

## Phase 1：理解需求

收集以下信息（最多问 2 个问题，其余用合理默认值推断）：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 目标功能 | 必须明确 | 用户想实现什么 |
| 语言/框架 | Python | 根据上下文自动判断 |
| 输出格式 | `.ipynb`（数据科学场景）/ `.py`（脚本场景） | 根据任务性质自动选择 |
| 数据/输入 | 使用示例数据或占位符 | 若用户有真实数据则使用 |

**判断输出格式**：
- 涉及数据分析、机器学习、可视化 → `.ipynb`（Notebook 格式，分块展示）
- 涉及脚本、工具、API 调用、自动化 → `.py`（脚本格式）
- 不确定时默认 `.ipynb`

---

## Phase 2：设计代码结构

生成前，先在脑中完成完整实现：

1. **确认技术路径**：选择最直接、最成熟的实现方式（不过度工程化）
2. **划分逻辑块**：将代码按功能分成 3-7 个独立段落（环境准备 / 数据加载 / 核心逻辑 / 输出展示）
3. **确认可运行性**：每块代码在上下文中可独立理解，整体串联后可直接运行
4. **准备示例数据**：若用户没有提供数据，生成简洁的内嵌示例数据，不依赖外部文件

---

## Phase 3：生成代码

### Notebook 格式（`.ipynb`）

使用 `Write` 工具创建文件。

**结构**：

```
[标题 cell]     一句话说明这段代码做什么
[环境 cell]     import + pip install（带注释说明每个库的用途）
[逻辑块 1]      markdown 说明 → code 实现
[逻辑块 2]      markdown 说明 → code 实现
...
[逻辑块 N]      markdown 说明 → code 实现
[结果展示 cell] 运行结果 / 输出验证
```

**每个逻辑块的格式**：

```
[markdown]  ## {块名称}：{一句话说明这块做什么}

            {2-3 句解释这块的逻辑和必要性。若涉及重要 API 或参数，说明关键参数的含义。}

[code]      # {块目的}
            # 关键说明：{重要参数或逻辑选择的理由}

            {完整实现代码}
            # 注：{若有非显而易见的逻辑，行内注释说明}
```

### 脚本格式（`.py`）

使用 `Write` 工具创建文件。

**结构**：用 `# ── {块名称} ──` 分隔各逻辑块，每块前有 2-3 行注释说明目的。

```python
#!/usr/bin/env python3
"""
{一句话描述脚本功能}
用法：python {filename}.py
"""

# ── 环境依赖 ──────────────────────────────
# 运行前确保安装：pip install {库名}
import {库}  # {用途}

# ── {逻辑块名称} ──────────────────────────
# {2-3 行说明这块做什么}
{代码}

# ── {下一个逻辑块} ─────────────────────────
...
```

## Phase 4：代码质量规范

**必须做到**：
- [ ] 代码完整，直接运行不报错（使用示例数据或内嵌占位符）
- [ ] 每个逻辑块有 markdown/注释说明其目的
- [ ] 关键 API 的重要参数有注释解释含义
- [ ] 变量命名语义清晰（`customer_df` 而非 `df2`）
- [ ] 有输出验证（`print` 或 `.show()` 让用户确认代码跑通）

**不需要做**：
- ❌ 完整的错误处理（用户会在真实场景中按需添加）
- ❌ 工厂函数/抽象层（除非任务本身需要）
- ❌ TODO 或骨架（直接给出实现）
- ❌ 多个实现方案对比（选最直接的一个）

---

## Phase 5：输出说明

生成完毕后告知用户：

1. **文件路径**
2. **运行方式**（一行命令或操作说明）
3. **可选后续**：
   - 针对某块逻辑深入解释
   - 替换示例数据为用户的真实数据
   - 扩展功能（如加错误处理、参数化、批处理）

---

## 语言与风格规范

- **注释语言**：跟随用户提问语言
- **技术术语**：保留英文，首次出现时附中文解释
- **语气**：简洁直接，注释解释「为什么这样做」而非仅「做了什么」
