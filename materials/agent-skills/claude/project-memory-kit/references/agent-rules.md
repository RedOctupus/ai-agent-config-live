# Agent 执行细则（按需读）

不拷进业务项目。改代码犹豫、涉及高风险、或要写测试汇报时再读。
项目活文档以 `docs/memory/MEMORY.md` 为准。

## 优先级

```text
阅读 / MEMORY 门闸  >  最小修改执行  >  测试验证  >  汇报格式
```

## 先读后写

编码前能回答 MEMORY 文末门闸。理解错误则后续全错。

## 执行

目标：正确、稳定、可验证、可回滚。不是优雅或「以后可能用到」。

- 只改当前任务必要文件和逻辑
- 禁止修 bug 时顺手重构、加功能时顺手改架构
- 禁止提前抽象（没有 3 个真实调用者不要上框架）
- 默认不新增依赖；必须加时说明理由、现有方案为何不够
- 禁止硬编码密钥；配置走环境变量 / `.env`（不提交 git）

## 必须先确认再改

数据库结构、接口协议、权限/认证、配置、部署、删除代码或数据。

可直接做：局部 bug、补测试、改文档、低风险小重构。

风险：LOW 局部/文档；MEDIUM 跨模块/新接口；HIGH 库、权限、部署、第三方。

## 测试

目标不是「能跑」，而是：需求对、旧功能没坏、能复现验证。

任意改动至少一种验证（单测 / 集成 / 手工）。未跑的测试必须写原因，禁止谎称通过。

**怎么选验证方式：**

| 改动 | 首选 | 判据 |
| --- | --- | --- |
| 纯函数 / 工具 / 规则 | 单测 | 快速、可重复、无外部依赖 |
| 跨模块 / 数据库 / 接口 | 集成 | 真库 / 真 HTTP，核对真实输出 |
| UI / 交互 / 展示 | 手工或浏览器 E2E | 真浏览器点一遍，对账页面数据 |

写验证必须给**可复现命令 + 实际结果**，禁止只写「已通过」。例如 `python -m pytest -k 'not test_sprint'` → `896 passed`，或 `node 09-advisor-pages.mjs` → 退出码 0。

交付时写 `docs/memory/tests/YYYYMMDD-任务名.md`。

## 当次汇报（对话里）

```text
读了什么
改了哪些文件（路径 + 一句原因）
怎么验证（命令 + 结果）
风险等级 + 是否需确认
未测什么、剩余风险
```

事实与推测分开；结论尽量带路径/命令证据。
