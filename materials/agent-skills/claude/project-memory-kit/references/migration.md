# 存量项目收敛 / 骨架升级（按需读）

不拷进业务项目。两种场景走本 playbook：

- **一、存量收敛**：目标项目已有 `docs/memory/` 但**不符合本骨架**（缺源文件、MEMORY 超长、战报堆在 MEMORY 里）。
- **二、骨架升级**：项目结构本来就合骨架，是 **kit 出了新版**（多了文件 / 改了维护口令），老项目要跟版。

两种场景都守同一条铁律：**只外移，不删除**——任何舍不得的内容都放回对应源文件，原地只留指针。外移的强制顺序见下。

## 外移的强制顺序（两种场景通用）

外移是「复制 + 删除」两步。凭记忆一次做完最容易漏——**尤其是决策条目**（「XX 未拍板」这类长得像备注，逐条搬时最常被跳过；实测丢过一条「MiniMax 未拍板」，靠人工回头对照才发现）。

1. **先复制到新处**，原处不动
2. **逐条回读原处对照**——按条目 / 关键词**点名核**，不靠通读印象
3. **确认零遗漏**后，才允许删原处
4. 跑 `python scripts/check-memory-size.py` 确认达标

## 一、存量收敛

### 什么时候走这里

- Init 时发现 `docs/memory/MEMORY.md` 已存在且体量/结构不合骨架。
- 已有 memory 系统（含旧名 `MANUAL.md`、或战报 / 仓库地图堆在 MEMORY 正文里）。

### 收敛步骤

1. **盘点现状**：列出 `docs/memory/` 下所有文件与各自行数；标记哪些是「快照/约束」、哪些是「源文件正文」、哪些是「战报/逐轮结果」、哪些是「跨阶段必知事实」（后者常被堆在 MEMORY 的「约束/特殊规则」节里）。
2. **建 annex/ 外移战报**：把 MEMORY 里的逐轮结果、逐缺陷状态、E2E 明细、复跑取证 → 新建 `annex/VERIFY-YYYYMMDD-任务名.md`；MEMORY 只留一行 `见 [VERIFY](annex/…)` 指针。研究摘录用 `NOTE-`。若存量仍是 `docs/memory/tests/` 或文件名 `TEST-LOG-*`，分别改成 `annex/` 与 `VERIFY-`；**不要**和仓库根目录的 pytest `tests/` 搞混。
3. **按骨架重建源文件**：缺哪个补哪个；把已有正文按性质归位：
   - 对方现在怎么办事 → `ENVIRONMENT.md`
   - 拆解条目 / 验收 → `REQUIREMENTS.md`
   - 选型 / 能力模块 / 分层 / 仓库地图 → `FRAMEWORK.md`
   - 端到端怎么走 → `FLOW.md`
   - 变更史 → `ITERATION.md`
   - 跨阶段必知事实（环境路径 / 账号位置 / 工具版本 / 研究结论 / 坑 / 已排除的路）→ `HANDOVER.md`
   - 外部对标 / 外部系统端点与本机路径 / 参考仓库 → `REFERENCES.md`（**只搬地址；研究正文另立 `annex/` 一份**）
4. **MEMORY 裁回 ≤400 行**：只留各阶段一句话 + 约束/入口 + §0 指针；跑 `python scripts/check-memory-size.py` 确认达标。
5. **不可丢内容用指针保留**：任何舍不得删的正文，都放回对应源文件，MEMORY 里留「见 X.md」指针，而不是留在 MEMORY 里。

### 注意

- 重命名旧 `MANUAL.md` → `ENVIRONMENT.md`，不要两份并存。
- 先查 git / 对话里是否还有旧内容，能恢复就恢复，不要用空模板盖掉进度。
- 收敛过程本身记一条 `ITERATION.md`（影响：MEMORY 体量）。

## 二、骨架升级（kit 出了新版，已有 `docs/memory/` 要跟上）

和「存量收敛」的区别：项目结构**本来就合骨架**，是 kit 新增了文件或改了维护口令，老项目要跟版。典型触发：`templates/` 多了文件（如 `HANDOVER.md`），或常驻口令变了。

1. **比对差异**：拿项目里的 `docs/memory/` + `AGENTS.md` + `.cursor/rules/project-memory.mdc` 逐句对照当前 `templates/`，列出缺哪些**文件**、缺哪些**口令**。别凭印象，逐句看。
2. **建缺的文件**：从 `templates/` 拷同名空白模板（kit 新版新增的文件，如 `HANDOVER.md`、`REFERENCES.md`）。**先查 git / 对话里有没有旧内容**，有则恢复，别用空模板盖进度。
3. **把散落的事实归位**：新文件建好后，把原先堆在别处的内容搬进去（如「跨阶段必知事实」常堆在 MEMORY 的「约束 / 特殊规则」节里）。**走上面的强制顺序**——这一步最容易丢东西。
4. **补 MEMORY 各节**：新文件要挂进 §0 指针、§5 文档资产表与阅读策略、§7 门闸。只加指针，不搬正文进 MEMORY。
   顺手过一遍存量 `TODO.md`：按模板的四条结构约定与验收下限改**形状**（父项只当分组名 / 不写「下面 N 项」/ 给不出验收的条目补量法或移 `HANDOVER.md` / 阻塞统一标记）——**只改形状，不改事实**。
5. **补常驻口令**：`AGENTS.md` 与 `.cursor/rules/project-memory.mdc` **逐句对照 `templates/` 补齐**。两处都是每轮注入，**必须同时改**——只改一处，不读 `.cursor` 的 Agent 就漏了。
6. **追加一行 `ITERATION.md`**：影响列写清动了哪些文件。
7. **跑门闸**：`python scripts/check-memory-size.py` 达标再收工。

> 第 5 步的清单**以 `templates/` 为准**，不要在别处维护第二份——枚举式清单一旦和模板分叉，老项目就永远补不进新口令（HANDOVER 那次就是这么漏的）。
