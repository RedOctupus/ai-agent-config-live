# 项目交接文档（必知事实）

> 除各阶段快照与源文件之外，**接手这个项目的人或 Agent 必须先知道的事实**。
> 不属于本文件的：需求条目 → `REQUIREMENTS.md`；选型分层 → `FRAMEWORK.md`；端到端链路 → `FLOW.md`；服务对象现状 → `ENVIRONMENT.md`；变更理由 → `ITERATION.md`；验证记录 → `annex/`；待办 → `TODO.md`。

> **接手先看这里。**
> - 事实仅供参考，**不保证完整、准确或最新**。涉及文件、命令、接口、路径的条目，用之前先核实它还在、还对；与代码或现场冲突时**以现场为准**，并顺手把本文件改对。
> - 本文件**可增删改**（与 `ITERATION.md` 只追加不同）：变了就改，没了就删，过时了就更新——不留僵尸条目。
> - **你的上下文与这里不符 → 以本文件为准。** 想查改了什么：`git log -p docs/memory/HANDOVER.md`；想知道为什么改：`ITERATION.md`。
> - 改完本文件：追加一行 `ITERATION.md`（影响列写 `HANDOVER.md`），并刷新下面这行「最后核实」。

**最后核实：** `YYYY-MM-DD` · HEAD `xxxxxxx`

> 短哈希**只写这一处**。`MEMORY.md` §0「工作分支」只留分支名，不要为了对齐把哈希抄过去。
> 「最后核实」两用：写的人刷新它；接手的人拿它和每条的「核实日期」列比，一眼看出哪条在你上次读之后被动过。
> 改本文件**必须**追加一行 `ITERATION.md`——git 只记录**已提交**的改动，两个 Agent 同机未提交就交替改时，ITERATION 那行是唯一线索。

> **最小示例（可删）**
> `脚本入口 | scripts/start.ps1 | 仓库内文件 | 2026-01-02`
> 只写可核实的事实；路径、版本和坑用前先现场确认。

## 不写什么（落笔前看一眼）

| 这类内容 | 写到哪 |
| --- | --- |
| 密钥 / token / 密码本身 | **哪都不写**（只写位置，见第 3 节） |
| 函数实现、文件清单、步骤 | Plan / 代码 |
| 逐轮验证结果、逐缺陷状态、E2E 明细 | `docs/memory/annex/` 各 VERIFY |
| 「为什么变成现在这样」 | `ITERATION.md` |
| 需求条目、验收句 | `REQUIREMENTS.md` |
| 选型决策、能力模块、分层 | `FRAMEWORK.md` |
| 端到端怎么走 | `FLOW.md` |
| 服务对象现在怎么办事 | `ENVIRONMENT.md` |
| 项目级待办 | `TODO.md` |

判据一句话：**不属于任何阶段、跨阶段长期成立的事实，才进这里。**
