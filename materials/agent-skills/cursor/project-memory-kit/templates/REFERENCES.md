# 外部参考（地址簿）

> **这是指针文件，不是研究文件。** 每条只放「是什么 + 去哪看 + 本项目的用途」。
> 原文摘录 / 提示词 / 阈值 / 规格正文 → 另写一份 `docs/memory/annex/NOTE-YYYYMMDD-短名.md`，这里只留指针。
> （实测踩过：把研究正文写进地址簿，最后不得不整段移出去。）
> **可增删改**（与 `ITERATION.md` 只追加不同）：不再用的条目**直接删**——地址簿最怕死链。

> **与 `HANDOVER.md` 的分界：**
> 关于**本项目**的事实（我们接在哪、配置在哪、有什么坑）→ `HANDOVER.md`；它的「证据或出处」列可以填本文件。
> 关于**外部事物**的入口（去哪个 URL / 哪个路径找）→ 本文件。
> 实测两者会成链：HANDOVER 记「Z-image 接在本机 8000，可选」，本文件记「Z-image 工程在哪个盘、preset 用 slug 不用文件名」。

> **什么时候加一条：** 要对标某个外部产品、接入某个外部服务、参考某个外部实现、换了工具来源时。

------

## （名称）（对标 / 外部服务 / 参考实现 / 来源）

```text
- **去哪看：** URL / 本机路径 / 端点 / 仓库 @ commit（写清「为什么是它」，例如 slug 而非文件名）
- **本项目用途：** 选型参考 / 能力对标 / 设计来源 / 已接入
- **相关指针：** 规格 / 计划 / 研究明细的路径
- **最近核实：** YYYY-MM-DD
```

> 照上面形状复制一节（**每条用 `##`**）；有了真实条目后删掉这节。

------

**不写什么（落笔前看一眼）**

| 这类内容 | 写到哪 |
| --- | --- |
| 原文摘录 / 提示词 / 阈值 / 规格正文（研究结论） | `docs/memory/annex/NOTE-YYYYMMDD-短名.md`，这里只留指针 |
| 本项目自己的路径、端口、配置位置 | `HANDOVER.md` §2 关键路径 |
| 选型决策（用不用它、为什么用它） | `FRAMEWORK.md` |
| 密钥 / token / 密码本身 | **哪都不写**（只写位置，见 `HANDOVER.md` §3） |
| 「什么时候接的、改过什么」 | `ITERATION.md` |

判据一句话：**这里放「外部事物的入口」，不放「我们做了什么的记录」。**
