# 需求迭代

> 每次需求讨论定稿、范围或架构变更追加一条。不要改历史条目，只追加。
> 记录变更，靠「影响」列区分：快照一句话 → MEMORY；大环境 → ENVIRONMENT；条目 → REQUIREMENTS；选型/模块 → FRAMEWORK；端到端怎么走 → FLOW；跨阶段必知事实 → HANDOVER；外部对标/外部系统地址 → REFERENCES。

> **改 `HANDOVER.md` 必须在这里追加一条**（影响列写 `HANDOVER.md`，原因写清为什么改）。
> HANDOVER 是**行内改**文件，旧值改完就没了；而 git 只记录**已提交**的改动——两个 Agent 同机交替改、还没提交时，这里是唯一的变更线索。

| 日期 | 变更 | 原因 | 影响（模块/文档） |
| --- | --- | --- | --- |
| YYYY-MM-DD | init 项目记忆 | 新项目 | MEMORY / ENVIRONMENT / REQUIREMENTS / FRAMEWORK / FLOW / HANDOVER / REFERENCES |
| 2026-01-02 | [示例，可删] R1 验收句变更 | 用户确认口径 | REQUIREMENTS |
