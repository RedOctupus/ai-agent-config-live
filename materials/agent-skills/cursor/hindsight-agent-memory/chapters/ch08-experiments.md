# Chapter 8: Experiments — LongMemEval & LoCoMo

## Core Idea
用「同底模有无记忆」的对照把架构贡献和模型规模解耦：GPT-OSS-20B 全上下文 39.0% → HINDSIGHT 83.6%（LongMemEval S），且开源小模型打赢配前沿模型的商业记忆系统。

## Frameworks Introduced
- **数据集（§7.1）**:
  - **LongMemEval**: 500 题、五能力——IE 信息抽取、MR 多会话推理、TR 时间推理、KU 知识更新、ABS 弃答。两个规模：S ≈ 115k token / 约 50 sessions，M ≈ 1.5M token / 约 500 sessions。
  - **LoCoMo**: 50 段人-人对话，平均 304.9 轮、9,209.2 token、19.3 sessions（最长 35），含图像多模态；测单跳/多跳/开放域/时间记忆。
- **评测方式（§7.2）**: LLM-as-a-judge——生成回答 + 标准答案一起给裁判模型，二元打分（0/1）看事实正确且不引入错误；多跳与时间题还检查是否恰当使用了检索记忆与时间上下文；ABS 题看是否在信息缺失时正确拒答。完整裁判提示词见 Ch 10。
- **实验设置（§7.3）**:
  - 事实抽取与反思都用 GPT-OSS-20B（主配置）；裁判 GPT-OSS-120B、temperature=0.0。
  - 记忆库配**中性画像**：S=L=E=3、β=0.2——因为基准测事实召回，不测偏好条件化（要避免强观点形成干扰）。
  - 三档配置：OSS-20B（记忆栈+生成都是 20B，单张高端消费级 GPU 可跑）；OSS-120B（记忆栈升级到 120B）；Gemini-3（记忆栈与裁判仍是 OSS-120B，Gemini-3 Pro 仅做最终作答）。
  - 注意：原文 token 预算写作「`<add>` tokens」——论文占位符没填，预算数值不可考。

### Baseline 来源与可信度（§7.4–7.5）
- LongMemEval 基线（FC GPT-4o、Zep、三个 Supermemory 配置）**直接取自 Supermemory 技术报告**，用的是他们自家的 GPT-4o 裁判设置。
- LoCoMo 基线（Backboard、Memobase、Zep、Mem0、LangMem、OpenAI）是 **Backboard 官方榜上各家自称的数字**，论文明说「作为参考点而非独立复现」。
- HINDSIGHT 自己的结果全部用同一个 GPT-OSS-120B 裁判重评，保证方法间可比——**跨行比较时注意裁判不同源**。

## Key Findings
1. LongMemEval：OSS-20B 记忆架构带来 +44.6 点（39.0→83.6），最大涨幅恰在长程题——multi-session 21.1→79.7、temporal 31.6→79.7、preference 20.0→66.7，说明图/时间感知检索缓解了长上下文稀释。
2. OSS-120B 记忆栈达 89.0%，Gemini-3 作答达 91.4%——全场最佳，超过 Supermemory+GPT-5 (84.6%)。
3. LoCoMo：从最强先前开源系统 75.78%（Memobase）提升到 83.18/85.67/89.61%；Open Domain 达 95.12% 最高，Gemini-3 配置 89.61% 与 Backboard 自称的 90.00% 基本打平，但记忆栈全开源。

## Mental Models
- 看记忆系统论文先找「同底模对照组」：只有 FC(OSS-20B) vs Hindsight(OSS-20B) 这一行能干净归因到架构。
- 拿基线数字时画个来源标记：自家裁判重评 > 报告引用 > 榜单自称，三种可信度不能混着比。

## Anti-patterns
- **跨裁判比较分数**: HINDSIGHT 行用 OSS-120B 裁判、Supermemory 行用其报告裁判，严格结论要谨慎。
- **用强偏好画像跑事实基准**: 会引入观点偏移污染正确率——所以实验锁 β=0.2。
- **忽略占位符**: 引用此文时别编造检索预算数字，原文是 `<add>`。

## Key Takeaways
1. 架构贡献的证据链 = 同底模 44.6 点提升 + 最大涨幅在长程题型。
2. 中性画像（S=L=E=3, β=0.2）是测记忆能力的正确姿势；测偏好一致性才应该开极端画像。
3. 全开源栈 89.61% 追平商业报告值，且发布了代码和可下钻的结果查看器。
