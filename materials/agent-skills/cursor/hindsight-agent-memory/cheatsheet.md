# Cheatsheet — HINDSIGHT 决策速查

## 决策规则（When X → Because Y）
| 触发情形 | 做法 | 理由 |
|---|---|---|
| 结果要喂 LLM 而非展示给人 | 用 token 预算 k 做检索接口，不用 top-k | 条数≠token 量，难度不同覆盖面应不同 |
| 查询含专名/术语 | 必开 BM25 通道 | 嵌入对专名不敏感（Ch 5） |
| 查询含时间表达 | 规则日期解析优先，失败才用 flan-t5 | 规则路径覆盖多数且低延迟 |
| 要召回「间接相关」记忆 | 图通道扩散激活，causal/entity 边加权 | 向量算不出共享实体与因果 |
| 多路结果要合并 | RRF（k≈60），不要加权分数融合 | 各通道量纲不可比，RRF 免校准 |
| 融合后要精度 | cross-encoder (ms-marco-MiniLM-L-6-v2) 重排 | 融合给多样性，重排给精度 |
| 存储对话 | 叙事事实 2–5 条/对话，五维齐全 | 碎片化丢推理链（Fig 3） |
| 回答「TA 是谁」类问题 | 查 observation 网络，不逐条拉原始事实 | 摘要已合成，省 token 去冗余 |
| 新事实与既有观点矛盾 | 走强化三步：筛候选→判关系→α 步长调 c | 直接覆盖会震荡，小步长稳定但响应 |
| 用户给新背景 | 归一第一人称再 LLM 合并 | 拼接导致提示词自相矛盾 |
| 测事实召回的基准 | 画像锁 S=L=E=3, β=0.2 | 强观点会污染正确率 |
| 测偏好一致性 | 开极端画像对照（如 S=1,E=5 vs S=5,E=1） | 同事实不同画像才显出条件化效果 |
| 评估记忆系统 | 找同底模「有无记忆」对照 | 只有这样才能归因到架构 |

## 数值与默认值
- **RRF 常数**: k = 60（论文示例值）
- **画像维度**: S/L/E ∈ [1,5]，中性 = 3；β ∈ [0,1]，事实基准用 0.2，0.5 = 中等，1 = 强立场
- **叙事抽取**: 每次对话 2–5 条事实
- **confidence c**: [0,1]；~1 强信念，中段暂定，低值易修正
- **强化步长 α**: (0,1)；小 = 稳定迟钝，大 = 灵敏易震荡；谨慎画像用更小 α
- **扩散激活衰减 δ**: (0,1)；causal/entity 边 μ>1，弱语义/长程时间边 μ≤1
- **causal 边权重**: 1.0；关系类型 {causes, caused_by, enables, prevents}
- **裁判**: GPT-OSS-120B，temperature = 0.0，输出必须 `\boxed{yes}`/`\boxed{no}`
- **时间格式**: `day_name, month day, year`（必须带星期几）
- **背景长度目标**: 几百字符内
- **观察条数**: 3–7 条/实体

## 迹象与气味（Tells & Smells）
- 答案里事实和推断混着 → 存储没分区，检查 opinion 是否独立成网络
- 「Alice 的事」查不全，只在全上下文时能答 → 缺实体链接，检查 ρ 消解与 entity 边
- 时间题全靠猜 → 没做显式时间解析，向量检索天然不擅长日期
- 换个会话人格就漂移 → 画像没持久化在 bank profile，只写在了单次提示词里
- 背景里同时存在两个出生地 → 缺 background merge，片段在裸拼接
- 检索结果超上下文 → 没做贪心装箱或预算没透传
- 抽取出的 'Emily' 和 'my roommate' 是两条 → 共指消解没做（附录标 CRITICAL）
- 把 'I don't have enough information' 存成观点 → A.2 排除项失效
