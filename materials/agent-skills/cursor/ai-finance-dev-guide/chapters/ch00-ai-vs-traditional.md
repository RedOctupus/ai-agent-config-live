# Chapter 0: 先搞清楚 — AI 项目和普通项目差在哪

## Core Idea
AI 项目共享传统软件流程，但必须在**概率输出、评测基线、版本化 AI 资产、静默失败、兜底、按 Token 计费、回归评测**七维上额外工程化，并跑通知识 / 评测 / 反馈三条闭环。

## Frameworks Introduced
- **AI 项目七维差异表**：输出概率性、正确性靠评测、核心资产含 Prompt+知识库+评测集、失败常表现为「看起来对」、兜底必须显式设计、成本随调用量×Token×重试、Prompt/知识库/模型变更必回归。
  - When to use: 立项答辩、解释「为什么要评测集和 Langfuse」
  - How: 用表格对照普通项目，逐条映射到本仓库章节（7.x、8.x、14.x）
- **三条闭环**：知识闭环（采集→切分→入库→更新）、评测闭环（黄金集→基线→回归）、反馈闭环（点踩→归类→回灌评测集）。
  - When to use: 排期与 DoD 设计
  - How: 每条闭环缺一环则效果不可控；反馈不得只改 Prompt

## Key Concepts
- **知识闭环**: 文档有效期与权限，避免召回废止政策
- **评测闭环**: 无基线则无法判断 Prompt 改动好坏
- **反馈闭环**: 线上 Bad Case 结构化回灌，而非口头修 Prompt
- **静默失败**: 不报错但内容错误，AI 项目最危险失败模式

## Mental Models
- Use 七维差异表 when 团队把 AI 项目当「调 API 小功能」
- Think of 三条闭环 as 与传统 CI 并列的「AI 运维面」

## Anti-patterns
- **只堆文档不做门禁**: 阶段产出未评审就进入下一阶段
- **改 Prompt 不跑评测集**: 感觉变好/变糟无判据

## Key Takeaways
1. 同样输入不保证同样输出 — 只能约束与评测，不能断言相等
2. Prompt、知识库、评测集与代码同级，必须版本化
3. 低置信澄清、无依据拒答、工具降级、转人工是设计项非可选项
