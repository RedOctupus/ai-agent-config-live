# Chapter 14: 运行监控、反馈与复盘（选修）

## Core Idea
上线后盯系统、模型、RAG、Agent、业务安全、体验六维指标；反馈带 trace_id 归类根因；复盘改流程不甩锅；答辩后问题入改进项。

## Frameworks Introduced
- **监控六维表**: 可用性/错误率；模型成功率与 Token 成本；RAG 无结果与低分；Agent 路由与步数；越权与适当性拦截；满意度与转人工率。
- **反馈闭环 14.2**: 点踩/纠错/转人工 → 归类(需求/数据/检索/Prompt/模型/工具/权限/性能) → 决定进哪条迭代线，禁止只改 Prompt。
- **复盘模板**: 现象、影响、根因、临时/长期措施、负责人、时间。

## Key Takeaways
1. 告警须有人负责与升级路径
2. 答辩视为发布评审，评委问题转 backlog
3. 教学项目可简化监控，但反馈→评测集机制仍建议保留
