# Chapter 7: AI 特有工程方法

## Core Idea
复杂度在把**不确定性关进笼子**：确定性优先、Prompt 版本化、上下文预算与记忆分层、成本/cache 设计、非确定性测试、AI 编码边界、风险登记、演示预案、失败实验日志与 ADR 并列。

## Frameworks Introduced
- **LLM 决策树**: 输出须确定 → 规则；可查库/接口 → NL2SQL/NL2API；否则 LLM + 兜底 + 评测集。金融适当性/金额/权限禁止交模型。
- **Prompt 生命周期**: 草稿 → 外置模板 → 版本+Owner → 变更触发回归 → 达标发布 / 未达标回滚 → 线上监控。
- **记忆三道闸门**: 分层(短/中/长) → 压缩为结构化画像/槽位 → 相关性重排 + token 预算 + 过期；跨 Agent 只传结论+依据 ID。
- **前缀缓存布局**: 稳定区(系统提示/工具定义) → 半稳定(检索片段按固定 key 排序) → 易变区(用户输入)；缓存键含模型+Prompt+知识库+工具 Schema 版本。
- **AI 测试对照表**: 断言关键事实/节点序列/工具 Schema+降级；Mock 录制；固定评测集回归。
- **Agent 防死循环四件套**: 回边出口、步数预算(~25)、重复状态指纹、时间/成本上限。
- **AI 编码四不交**: 契约与公共能力、权限风控适当性、金额精度、评测集阈值。
- **AI 产出四底线**: 讲得清、跑得动、有测试、无幻觉依赖。
- **演示四时点预案**: T-3 新机 clone≤15min；T-1 备份视频；T-30min 冒烟必问句；现场禁止改代码。
- **失败实验日志**: 现象(原话)、证据(trace_id)、分层归因、根因、防复发(进评测集/DoD/单测) — 与 ADR(成功决策)并列。

## Key Takeaways

2. 写操作与状态查询禁止缓存
3. 答辩 -20 分「无法启动」用 docker-compose 与演示预案对冲
