# Chapter 6: Agent 的评估

## Core Idea
评估为 Agent 系统设计提供科学依据，帮助区分真正的能力提升与随机波动。评估对象不应只是模型本身，而是 **模型 + Harness 的组合体**。同一模型在不同 Harness 中表现可能差异悬殊；完善的评估体系能区分“模型能力不足”和“Harness 设计缺陷”，并支持快速跟上模型演进。

## Frameworks Introduced

- **评估的三层体系**：
  1. 评估环境（在哪里测）：工具调用型、人机交互型、仿真环境
  2. 评估方法（怎么判）：数据集设计、指标体系、LLM-as-a-Judge、配对比较、模型排名
  3. 评估驱动决策（测了干什么）：模型选型、架构优化、持续迭代、统计显著性判断
- **评估对象是模型 + Harness 的组合**：优化 Harness 有时比换模型更有效。
- **模型替换实验（Model Swap）**：固定 Harness，只更换模型，判断瓶颈在模型还是 Harness。
- **消融实验（Ablation Study）**：逐一关闭 Harness 的某个组件，判断该组件的真实贡献。
- **Rubric 评分**：把 Agent 轨迹拆成多个可检查维度，逐项评分而不是只给总分。
- **幻觉否决机制（Hallucination Veto）**：幻觉是正交的否决项，包含虚假事实的回答无论多流畅都应判负。
- **工具调用型评估环境**：自动化、可复现、依赖工具返回值判断结果。
- **人机交互型评估环境**：适合需要主观判断、多轮对话、用户体验的任务。
- **评估数据集设计原则**：任务描述精确、复杂度层次化、可验证性、客观性、系统性分布、质量控制迭代。
- **LLM-as-a-Judge**：用大语言模型作为评委自动评分，但需逐项打分、引用证据、证据不足时拒绝评分。
- **配对比较与模型排名**：两两比较模型表现，避免绝对分数难以对齐的问题。
- **评估驱动的模型选型**：在自己的评估集上测试，避免新模型公开基准好但特定任务退化。
- **统计显著性**：判断分数差异是否真实可信，而非随机波动。
- **Agent 可观测性**：记录轨迹、工具调用、中间状态、延迟、成本，为评估和诊断提供数据。
- **生产级内部评估基础设施**：消融、A/B 测试、特性开关、提示词敏感性评估、隐私感知分析。
- **仿真环境**：连接评估与后训练的桥梁，提供模型练习的真实场地。

## Key Concepts

- **Evaluation Harness**：评估套件，包含环境、数据集、指标、评分器。
- **Rubric**：评分量表，把任务拆成多个维度逐项评分。
- **Ablation Study**：消融实验，判断各组件贡献。
- **Model Swap**：模型替换实验，定位瓶颈。
- **LLM-as-a-Judge**：用 LLM 作为自动评委。
- **Paired Comparison**：配对比较，两两对比模型输出。
- **Regression**：模型新版本在某些任务上性能退化。
- **Statistical Significance**：统计显著性，判断差异是否可靠。
- **Observability**：可观测性，记录运行轨迹和中间状态。
- **Simulation Environment**：仿真环境，可控的真实任务模拟。
- **Tool-call Evaluation**：基于工具调用轨迹的自动评估。
- **Human-in-the-loop Evaluation**：人机交互型评估。

## Mental Models

- **Evaluate the system, not the model**：模型只是系统的一部分，Harness 的优化同样关键。
- **No measurement, no improvement**：没有可重复评估体系，迭代方向只能靠直觉。
- **Rubric > vague score**：把轨迹拆成可检查的维度，比模糊总分更有诊断价值。
- **Hallucination is a veto**：再流畅的回答，包含虚假事实就是失败。
- **Your benchmark > public benchmark**：公开基准好不代表你的任务好，必须自建评估集。
- **Evidence over judgment**：评分必须引用轨迹证据，证据不足时拒绝评分。
- **Evaluate for model evolution**：评估体系的首要价值是快速跟上模型演进，而不是给当前系统打分。

## Anti-patterns

- **只评估模型不评估 Harness**：看不到工程优化的空间。
- **没有回归测试**：升级模型后不知道哪些任务退化。
- **评分标准模糊**：只给总分，无法诊断问题。
- **忽视统计显著性**：把随机波动当真实差异。
- **没有边界场景**：只测成功路径，不测失败和陷阱。
- **LLM-as-a-Judge 不引用证据**：评委给出模糊总分，无法审计。
- **评估数据集和实际任务脱节**：在 toy 数据集上表现好，生产环境失灵。

## Code Examples

```text
// 客服退款任务的 Rubric 评分示例
任务：用户要求退掉3天前的订单 #12345，金额 ¥299，政策：7天内全额退款。

维度            标准                        得分  理由
操作正确性      退款金额、订单号是否正确      4    正确查询并发起 ¥299 全额退款
政策合规性      是否遵循 7 天退款政策         4    订单在退款期内，符合政策
信息完整性      是否告知金额、到账时间、编号  4    三项关键信息均已告知
幻觉检测        是否编造不存在的信息          通过  所有信息均来自工具返回

结果：通过。幻觉作为否决项，一旦编造信息则整体失败。
```
- **What it demonstrates**：Rubric 把一次 Agent 轨迹拆成可检查维度，既能量化质量，也能定位问题。

## Worked Example

**场景：判断瓶颈在模型还是 Harness**

假设 Coding Agent 在修复 bug 任务上得分低：
1. **消融实验**：关闭“代码规范”上下文 → 分数下降 → 说明规范很重要
2. **模型替换实验**：把 GPT-4 换成 Claude 3.5，分数不变 → 说明瓶颈不在模型能力
3. **结论**：改进方向是优化 Harness（上下文组织、工具定义、测试流程），而不是换更贵模型

这是评估体系的核心价值：区分“模型能力不足”和“Harness 设计缺陷”。

## Key Takeaways

1. **评估模型 + Harness 的组合**：同一模型在不同 Harness 中表现可能天差地别。
2. **三层评估体系**：环境、方法、决策，缺一不可。
3. **Rubric 和证据引用是自动评估的基础**：模糊总分无法诊断问题。
4. **幻觉是否决项**：包含虚假事实的回答无论多流畅都不可接受。
5. **自建评估集比公开基准更重要**：新模型可能在公开基准上更好，但在你的任务上退化。
6. **统计显著性避免误判**：分数差异必须可靠，否则可能优化噪声。
7. **评估体系是跟上模型演进的速度优势**：有评估体系能在数小时内做切换决策，没评估体系只能凭直觉。
