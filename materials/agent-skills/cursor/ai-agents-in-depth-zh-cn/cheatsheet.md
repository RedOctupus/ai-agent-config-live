# Cheatsheet

快速参考：决策规则、权衡矩阵、阈值与反模式信号。

## 1. 核心决策规则

### 1.1 当任务需要 Agent 时
- **如果任务是单次问答、答案明确** → 用普通 LLM 调用即可，不必用 Agent。
- **如果任务需要多步骤、调用工具、根据反馈迭代** → 用 Agent。
- **如果任务涉及外部系统、文件、代码、网络** → 必须为 Agent 配备工具。
- **如果任务结果可客观验证（测试通过、订单状态、金额）** → 适合评估驱动优化。

### 1.2 上下文工程 vs 后训练
- **如果问题能用清晰的 system prompt + 工具定义 + 示例解决** → 上下文工程优先。
- **如果模型反复学不会格式/流程，且已有高质量示范数据** → 考虑 SFT。
- **如果需要开放环境决策、探索、泛化到新场景** → 考虑 RL（先有仿真环境）。
- **如果数据不足或环境不真实** → 不要微调，继续优化上下文和工具。

### 1.3 通用工具 vs 专用工具
- **如果操作参数简单、可组合、变化频繁** → 通用工具（Bash、Code Interpreter、Read/Write/Edit）。
- **如果参数复杂、需要强类型校验、安全关键** → 专用工具（结构化 schema）。
- **如果工具数量超过 100 个** → 必须引入主动发现机制和分层组织。

### 1.4 共享上下文 vs 隔离上下文（多 Agent）
- **如果角色强相关、需要完整继承用户对话历史** → 共享上下文（继承式协作）。
- **如果职责清晰、需要模块化、可扩展、可审计** → 隔离上下文 + 显式通信（隔离式协作）。
- **默认选择**：隔离上下文，通过共享文件系统或消息总线传递产物。

### 1.5 实时交互 vs 深度思考
- **如果用户要求低延迟响应（语音、GUI 操作）** → 用快思考维持实时，慢思考后台异步处理。
- **如果任务需要复杂推理但可等待** → 直接调用后台大模型，无需实时交互层。
- **如果动作不可撤销（机器人、支付）** → 实时快思考行动必须有可挽回机制或人类确认。

## 2. 决策树

```
开始设计 Agent
│
├─ 任务是否可一步完成？
│  ├─ 是 → 用 LLM 直接回答
│  └─ 否 → 进入 Agent 设计
│
├─ 是否需要外部工具/数据？
│  ├─ 否 → 纯推理/生成 Agent，重点在上下文和提示词
│  └─ 是 → 设计工具集
│
├─ 工具数量是否 > 100？
│  ├─ 是 → 引入 MCP + 主动发现 + 分层组织
│  └─ 否 → 普通工具定义即可
│
├─ 是否需要跨会话记忆？
│  ├─ 是 → 设计用户记忆 + 知识库（RAG/结构化索引）
│  └─ 否 → 单 session 上下文工程足够
│
├─ 是否需要多 Agent 协作？
│  ├─ 是 → 选择隔离上下文 + 显式通信；设计角色与接口
│  └─ 否 → 单 Agent 设计
│
├─ 是否需要实时交互？
│  ├─ 是 → 设计快慢思考解耦；全双工/异步架构
│  └─ 否 → 普通轮次式交互
│
└─ 是否需要持续优化？
   ├─ 是 → 建立评估体系 + 持续进化闭环
   └─ 否 → 静态 skill + 工具即可
```

## 3. 权衡矩阵

### 3.1 上下文 vs 成本
| 策略 | 上下文质量 | Token 成本 | 延迟 | 适用场景 |
|---|---|---|---|---|
| 全量加载 | 高 | 极高 | 高 | 短任务、关键决策 |
| 分层压缩 | 中-高 | 中 | 中 | 长对话、多轮任务 |
| 按需检索 | 中 | 低 | 中 | 知识库、用户记忆 |
| 子 Agent 隔离 | 局部高 | 低 | 低 | 复杂任务分解 |
| 缓存复用 | 不变 | 极低 | 低 | 系统提示、工具定义、稳定知识 |

### 3.2 工具设计形态
| 形态 | 开发维护成本 | 调用可靠性 | 灵活性 | 适用场景 |
|---|---|---|---|---|
| 专用工具 | 高 | 高 | 低 | 参数复杂、安全关键、稳定 |
| Skill + 通用执行器 | 低 | 中 | 高 | 流程变化快、模型能力强 |
| 通用工具组合 | 低 | 中 | 高 | Coding Agent、通用 Agent |

### 3.3 模型后训练选择
| 方法 | 数据需求 | 成本 | 稳定性 | 泛化能力 | 适用场景 |
|---|---|---|---|---|---|
| 提示词工程 | 无 | 低 | 高 | 低-中 | 格式、流程、简单约束 |
| SFT | 几千-几万示范 | 低 | 高 | 中 | 指令遵循、格式、风格、稳定流程 |
| RL | 任务 + 奖励函数 | 高 | 中-低 | 高 | 开放决策、探索、需要泛化 |

### 3.4 多 Agent 通信机制
| 机制 | 同步/异步 | 数据形态 | 适用场景 | 主要风险 |
|---|---|---|---|---|
| 工具调用参数 | 同步 | 结构化小数据 | 直接调用子 Agent | 耦合、阻塞 |
| 共享文件系统 | 异步 | 大产物、持久化 | 产物传递、流水线 | 并发冲突、版本混乱 |
| 消息总线 | 异步 | 消息、事件 | 并行协调、解耦 | 编排复杂度、消息丢失 |

### 3.5 语音交互架构
| 架构 | 延迟 | 自然度 | 可打断 | 实现复杂度 | 适用场景 |
|---|---|---|---|---|---|
| 级联 | 高 | 低 | 弱 | 低 | 智能音箱、简单客服 |
| Omni（turn-based） | 中 | 中 | 中 | 中 | 移动语音助手 |
| 全双工 | 低 | 高 | 强 | 高 | 自然对话、实时协作 |

## 4. 阈值与默认值

- **上下文窗口超过 50K tokens** → 优先使用分层压缩 + 按需检索，而非全量加载。
- **工具数量超过 100** → 引入主动发现、分层、MCP 组织。
- **对话轮次超过 20 轮** → 主动做上下文摘要或压缩。
- **工具调用失败率 > 5%** → 检查工具描述和 schema 质量。
- **幻觉作为否决项**：任何编造事实的输出直接判负，无论多流畅。
- **统计显著性**：对比实验至少需要能区分随机波动的样本量；效应量小则增加样本。
- **SFT 数据量**：几千到几万条示范通常足够建立稳定基线。
- **RL 训练成本**：通常是 SFT 的几十到上百倍，需先有仿真环境。
- **实时语音延迟预算**：超过 1-2 秒就会明显影响用户体验。
- **多 Agent 协调开销**：如果协调成本超过并行收益，改为单 Agent 或更简单流程。

## 5. 反模式信号（Tells & Smells）

- 模型反复输出格式错误 → system prompt 格式设计不够清晰，或缺少 few-shot 示例。
- 模型调用工具时传错参数 → 工具 schema 描述模糊或示例不足。
- 工具调用失败导致 Agent 卡住 → 缺少错误处理和重试/降级策略。
- 同一问题每次答案不同 → 缺少稳定上下文或评估体系。
- Agent 在多轮后“忘记”用户之前说的话 → 上下文未正确维护或未做摘要。
- 新模型上线后部分任务变差 → 缺少回归测试和自有评估集。
- 多 Agent 系统互相推诿或重复工作 → 角色职责和接口定义不清晰。
- 实时交互 Agent 响应慢 → 快慢思考未解耦，或深度推理阻塞了实时路径。
- Agent 在边界 case 上表现差 → 缺少边界场景评估和训练数据。
- 更新 Agent 后旧能力退化 → 缺少回归测试和持续验证机制。
- 用户反馈好但业务指标差 → 评估指标与用户价值不一致，需重新对齐奖励函数或 Rubric。
- 知识库回答过时 → 缺少时效管理和更新机制。
- 多 Agent 共享上下文无限膨胀 → 应从共享上下文切换到隔离上下文 + 显式通信。
- 语音助手在不恰当的时候插话 → VAD / 轮次检测过度敏感，考虑全双工架构。

## 6. 快速检查清单

### 设计新 Agent 时
- [ ] 明确任务是否需要多步骤、工具、迭代
- [ ] 确定工具集（通用 vs 专用）
- [ ] 设计系统提示词（人格、格式、组织、内容）
- [ ] 定义工具 schema（名称、描述、参数、示例）
- [ ] 规划错误处理和恢复策略
- [ ] 确定是否需要用户记忆 / 知识库
- [ ] 确定是否需要多 Agent 协作
- [ ] 确定是否需要实时交互
- [ ] 建立评估数据集和 Rubric
- [ ] 设计持续进化闭环（如适用）

### 评估 Agent 时
- [ ] 评估对象是否包含模型 + Harness 组合
- [ ] 是否同时测成功路径和边界/失败路径
- [ ] 是否有可重复的评估环境
- [ ] Rubric 是否逐项评分并引用证据
- [ ] 幻觉是否作为否决项
- [ ] 是否有统计显著性判断
- [ ] 是否有模型替换和消融实验
- [ ] 是否有回归测试

### 多 Agent 设计时
- [ ] 每个 Agent 的角色和职责是否清晰
- [ ] 选择共享上下文还是隔离上下文
- [ ] 通信机制（工具参数 / 共享文件 / 消息总线）
- [ ] 产物格式和接口协议是否明确
- [ ] 是否有冲突解决机制
- [ ] 关键决策点是否有人类介入
- [ ] 是否有跨 Agent 可观测性

### 实时交互设计时
- [ ] 延迟预算是否明确
- [ ] 快思考与慢思考是否解耦
- [ ] 是否支持打断和意图切换
- [ ] 实时动作是否可挽回
- [ ] 是否有降级策略（如网络中断）
- [ ] 是否优先用代码/API 替代 Computer Use
