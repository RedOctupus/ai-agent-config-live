# Lifecycle analysis

Use for L2/L3 work after the level gate.

| Stage/state | Entry | Role task | Agent business result | Evidence | State change / next |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

Ask:

1. What starts the lifecycle and what object changes state?
2. Which role owns each transition and which actions require human confirmation?
3. What context/evidence is required, missing, late, contradictory, or repeated?
4. What is the closure condition? What happens on reject, reopen, escalation, recurrence, or handover?
5. Which downstream domain consumes the result and how does state return to the project flow?

For responsibility work, keep assignment and post-action verification in one task lifecycle:

```text
create → assign → accept → execute → submit → verify → human decision → close / reopen / escalate
```

Handover requires explicit acceptance; lack of a later action is not proof of acceptance or rejection.
