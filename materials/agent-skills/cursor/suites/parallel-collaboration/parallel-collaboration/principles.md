# 并行开发三条思想

面向多人 vibecoding：每人代码量大，交叉修改易产生冲突。三条思想让模块尽量独立、后期再收敛。

## 契约思想

> 别人没有，你也可以写

契约先行：跨模块接口、数据格式、目录边界先定好，别人模块未完成时，调用方也能按契约并行开发。

## Legacy（兼容层）思想

> 尽量不直接修改他人代码

需要扩展或改动他人模块时，不直接改其核心业务代码，而是在模块边界新增包装、适配、桥接层。后期联调稳定后再统一收敛删除。

## Mock 思想

> 依赖别人的数据，别人还没做好，你就先 Mock

数据依赖未就绪时，按数据契约先 Mock，通过统一服务层接入；真实接口完成后只换服务层实现，业务页面尽量不动。

## 阶段顺序

```text
契约（阶段 0）
    ↓
并行开发期：兼容层（阶段 1）+ Mock（阶段 2）可同时进行
    ↓
清理收敛（阶段 3）：删兼容层、切真实接口、清 Mock
```

## 与其他 Skill 的衔接

| 时机 | 建议配合 |
| --- | --- |
| 需求尚未定清 | `brainstorming` |
| 定完契约后拆实现计划 | `writing-plans` |
| 按方案写代码 | `test-driven-development` |
| 清理前验证 | `verification-before-completion` |
| 多人独立任务 | `dispatching-parallel-agents` |
