# 选择指南：先找到为什么失败

这份指南是工程决策方法。模块含义见 [module-contracts.md](module-contracts.md)。

## 排查位置

拿一条具体的“输入历史 → 当前问题 → 错误输出”做判断，而不是从用户说“想上记忆架构”直接选技术。

| 可观察的失败 | 首先检查 | 合理的最小方向 |
|---|---|---|
| 记不住本轮收集的表单字段 | 会话状态和流程状态是否持久化 | `simple`：会话状态/状态机 |
| 把退款状态或任务成功说错 | 是否查权威系统，是否把计划当执行 | `simple`：业务接口与事件状态；必要时 P |
| 事实根本没存下来 | 原始来源、抽取漏项、触发遗漏 | P + N，或直接保存结构化事件 |
| 找到“做了 A”却解释不了理由 | 记忆是否切碎，决定/理由是否丢失 | N，不必先增加图 |
| 同一对象换了称呼就漏检 | 实体 ID、别名、身份归属 | P + E + 现有检索 |
| 更新偏好后仍用旧信息 | 时间、适用条件、更新与检索过滤 | P + T；已有摘要再接 S |
| 介绍用户太贵或摘要不更新 | 原始事实、摘要依赖、后台版本 | P + S；复杂历史再接 T/E |
| 专名漏检、语义命中不全 | 精确匹配与语义通道盲区 | R 的必要通道，按覆盖率决定是否重排 |
| 需要的证据在关联事件中 | 实体关联是否足够；是否真需多跳 | E + R；有案例支持才接 G |
| 回答重复后猜测进入档案 | 归属、独立证据识别、摘要输入 | P + 回流契约；现有摘要修复即可 |
| 同一建议不能随反证修正 | 是否真的需要长期判断，证据是否追溯 | P + O + R，按需要接 T |
| 正确证据都在上下文仍答错 | 提示、结构、标签、引用与回答契约 | 修读取后的消费过程，通常无需新存储 |

单一症状不证明唯一根因。例如“旧画像推荐”也可能是消费方没使用正确返回值；先对照实际 trace。

## 三种路线

### simple

业务只需要单轮/单任务字段、有限状态、权威状态查询、已存在结构化事件的检索或小规模显式偏好时，可采用简单机制。输出具体状态字段、有效期/清理或完成规则、读取时机及验收轨迹。

不要为了“完整”加入 Opinion、全量叙事抽取或实体图。需要跨会话不自动意味着 full；一个有来源的偏好表也可以长期持久化。

### partial

痛点集中且现有系统可提供其他职责时采用。列出选择模块及由谁提供依赖。例如现有 CRM 提供身份 ID、数据库提供历史偏好，则设计摘要与检索契约即可，不能为每个模块重复建库。

常见组合：

- P + T：持久化偏好、追溯适用范围与更新。
- P + N + E + R：跨会话事件解释，无长期主观观点。
- P + S：基于可信来源范围生成实体简介。
- P + O + R：复用现有证据库维护长期假设/建议；E/T/S 按案例增加。

此处 P 也可由现有数据的来源 ID、权限范围、类型字段提供，不要求迁移为独立模块。

### full

当业务明确要求以下四类记忆共同参与持续闭环时，采用 full 作为目标逻辑设计；交付仍可分阶段，不要求先部署局部系统再证明失败：

- 外部信息以及当前 Agent 自身的行动/建议历史。
- 基于累积事实的中立实体摘要。
- 有证据、适用条件和修订历史的长期判断。
- 新信息、检索、回答、回流与派生更新的持续闭环。

这些是需求证据，不是数量打分。路线描述目标职责范围，实施阶段描述交付顺序；full 的首个切片可以只实现部分能力。缺少某类业务用途时仍选择 partial，不为了满足四类而制造需求。用户明确要求完整教学原型也可以 full，但应标明原型用途和哪些能力尚无生产痛点支持。完整逻辑不强制 Neo4j、所有图边、所有检索通道或鲜明人格。没有长期判断需求时，不仅因为“会聊天”就引入 O。

## 推荐记录

简短问题用几句话；复杂项目可以使用这份紧凑记录：

```yaml
route: partial
goal: 能区分用户过去与当前的办公偏好
failure: 更新为混合办公后，旧摘要仍要求只投远程岗位
known: 现有数据库保留原始对话和 user_id
assumptions: 当前没有有效期字段；需检查实际 schema
selected: [P, T, S]
reuse: 现有数据库、检索、后台任务执行器
deferred: E 与 G 当前无别名或多跳问题；O 非事实偏好查询所需
first_slice: 偏好修订记录、摘要失效、当前查询过滤
acceptance: 过去与当前分别回答正确，旧后台任务不覆盖新版
```

该格式是示例，字段按用户任务裁剪。对预算、延迟等未知限制写出方案影响，不编造用户已承诺的数字。
