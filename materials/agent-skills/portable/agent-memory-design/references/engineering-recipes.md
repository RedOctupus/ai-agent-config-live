# 工程配方：按痛点选最小切片

本文件均为工程示例。字段和接口为设计示意，不是某 SDK 的真实调用。按现有存储/队列/模型调整；推荐具体当前依赖时查官方能力与项目版本。

## 配方 A：有限任务与权威状态

适用：客服填表中途忘字段、Agent 把“准备退款”当成已退款。

- 路线：simple。任务状态保存 task_id、已收集字段、当前阶段；退款/工单完成状态从业务系统读取。
- 写入：用户提供字段更新会话状态；业务接口回执更新对应执行事件。回答只能表达已有事件覆盖的结果。
- 读取：回答前查当前任务和权威状态，历史记忆只提供沟通过程。
- 首个切片：一个任务流程的持久化、查询和完成判定；无需 LLM 抽取业务状态。
- 验收：中断后恢复字段；提交失败或超时不能说成功；历史承诺不覆盖权威状态。

## 配方 B：偏好变化和当前摘要

适用：用户不再只考虑远程，却仍收到只投远程的建议。

- 路线：partial，P + T；已有摘要则接 S，查询接口可复用。
- 必要数据：user_id、属性/值、原始消息 ID、提及时间、有效范围、修订关系。保留条件，如“照顾家人期间”；未知生效日期不编造。
- 写入：区分“偏好改变”和“之前记录错了”；当前偏好投影与历史分开维护。提交后使相关摘要失效。
- 读取：查询明确 current/as_of；当前推荐不能只用陈旧摘要。并发刷新使用输入版本条件提交。
- 首个切片：只改办公模式这一属性，验证后扩展其他偏好。
- 验收：过去回答“只远程”、现在回答“也接受本地混合”；晚到的过去事件不覆盖当前；旧摘要任务不能覆盖新版本。

## 配方 C：跨会话项目解释

适用：问“为什么当时优先部署”，系统只找到“先部署”，或者项目别名无法连通。

- 路线：partial，P + N + E + R；T 在时间问题中增加。
- 必要数据：项目标准 ID/别名、事件叙事、来源、建议/接受/执行/结果类型和时间。
- 写入：保留决定理由和被否决方案；将“知识库助手”“KnowledgeBuddy”等明确别名关联。不能用名称相似强合并另一个项目。
- 读取：按项目身份和时间取相关事件，再按问题排序、预算装入；先确保理由与结果都在证据中。
- 首个切片：复用现有数据库，以项目关联表扩展候选；无图数据库也可实现。
- 增加 G 的条件：回放证明直接检索与实体展开仍漏掉跨项目或多跳解释链。
- 验收：可解释当时理由和当前变化；查询带预算后仍保留必要证据链，不只返回结论。

## 配方 D：回答回流污染

适用：Agent 重复建议后，档案里出现用户从未确认的能力或偏好。

- 路线：partial，P + 现有 S/抽取流程修复。详细规则见 [writeback-and-provenance.md](writeback-and-provenance.md)。
- 必要数据：source_event_id、source_role、subject、命题类型、claim_mode、原证据依赖。现有原始消息可直接作来源。
- 写入：分类候选后做目标视图约束；Agent 推断不写用户属性事实。建议事件可进入 B；用户接受另记事件。
- 更新：原数据被纠正时刷新依赖；回流重述保留引用、去重，不重新强化。
- 首个切片：修抽取与摘要输入，保留现有检索；用一条受影响属性完成闭环。
- 验收：多轮/多 Agent/重试后，建议不升级为属性；工具事实的重复转述不新增独立证据。

## 配方 E：长期辅导的完整闭环

适用：长期求职/学习辅导明确需要事实与行动历史、中立简介，以及会随证据变化的判断共同工作。仅需项目事实与历史建议、没有摘要或持续判断用途时选 partial；“辅导”这个业务名称本身不是 full 条件。

- 路线：full 的四类逻辑记忆；各查询通道按失败案例实现。
- 写入：外部陈述/工具结果进入 W；实际交互和行动进入 B；相关变化使 S 失效、安排 O 评估。
- 读取：事实型问题读 W/B/S 且能追溯；建议问题读取事实和带类型/条件的 O。问题预算与强制范围贯穿各通道。
- 生成：回答保留证据与判断区别；只有有长期用途时提交观点候选。Agent 配置只影响表达与权衡，不重写事实。
- 回流：应用明确保留内容和事件提交点，接同一 Retain 契约；保存建议不代表用户执行。
- 首个切片：在一个用户与一个辅导任务上串联底层证据、一个摘要和一条可修订观点，先证明回流不循环强化。
- 验收：能解释过去建议、识别新能力证据、修订适用条件；撤回证据后不继续使用受影响的当前强结论。

## 预算、延迟和存储选择

- 优先复用已有 ID、事件流、数据库、全文/向量索引和后台任务。选择关系型数据库、图库或其他存储应对应访问模式与规模，不对应论文图标数量。
- 单通道足够时不融合；有专名盲区再加词法，有间接关系盲区再扩图。语言适配、词法索引和重排实际能力需要核验；普通全文索引不自动提供 BM25。
- 区分候选数量 candidate_limit、RRF 常数 C、最终 token_budget。图扩展依赖种子；独立搜索通道可并行。
- 预算包括类型、来源、时间、格式开销及支持解释所需片段。零预算返回空证据；单条过长时回源抽取有来源的相关段或声明缺口，不能通过无来源裁剪改变命题。
- 原始来源与关键事实何时对查询可见须写清。摘要等派生工作可异步；等待要求取决于是否需要 read-your-writes，一律异步或一律同步都不合适。
- 用实际观测的 token、调用数、候选数、P50/P95 延迟和后台刷新延迟估算成本；没有运行数据则给估算方法，不捏造金额或目标值。

## 迁移和降级

对已有系统采用小范围双读/影子查询：保留旧读取路径，增加来源/类型等字段与一个业务切片；对照真实历史回放后再切流。不要批量把旧摘要认作独立原始事实；旧数据无来源时保持未知地位。

回退关闭新派生视图或新检索通道，底层来源保留可恢复性；回退不能取消范围和事实归属约束。若用户没有要求实施，这些是计划，不执行真实迁移。
