# 模块契约与可替换实现

以下是基于 Hindsight 思想拆分的工程能力。名字是职责标识，不规定部署数量。原论文的 W/B/O/S 为逻辑分类；模块 P/N/E/T/S/R/G/O 是本技能的工程拆分，两者不要混称。

每个被选能力需闭合：输入、输出、依赖、拥有者、触发、失败/降级、成本、验收。已有组件满足职责时直接复用。

## P：来源、类型与范围

- 输入：带来源身份的消息、工具响应、业务事件或文档。
- 输出：可追溯来源与命题/事件记录，注明主体、信息地位、适用范围和状态。
- 实现：复用原消息/事件 ID；在候选记录上保留来源角色与支持关系。`reported` 是自述/转述，`observed` 是来源实际覆盖的观察，`inferred` 是推断，`repeated` 是重述；可用现有字段表达，无需照搬枚举。
- 依赖/触发：先确定记忆主体、租户/用户/项目边界及信息所有者；每次持久化或派生更新适用。
- 降级：来源不足时保留未核实归属或不写入目标事实视图；不要去掉归属使记录更“干净”。
- 成本/验收：元数据与依赖维护；检验建议不会变成用户事实，别的用户的记录不会被读入。

`source_role` 不等于真伪标签。用户陈述可以证明表达过偏好；工具结果只支持其实际返回内容；Agent 回答有原始证据时可复述事实，但不能作为独立佐证。

## N：叙事抽取

- 输入：一段可关联的交互及其原始来源、消息时间。
- 输出：自包含事件，保留主体、关键请求、提议/决定、显式理由和结果，附来源片段。
- 实现：按业务事件或决策组织，不按每句机械切块，也不将整个长期历史压成一条。结构化工具事件通常直接入库，无需多做一次 LLM 抽取。
- 依赖/触发：P；交互完成或增量写入时。长期会话需处理重叠窗口去重。
- 降级：保留原文，可从来源回退检索；未知时间/原因保持未知。
- 成本/验收：抽取调用与较长记忆；回放“为什么当时选 A 而不选 B”，检验理由没有丢失。

论文的抽取粒度、星期格式与模型不是通用强制参数。日期和五个 W 缺失时不能为填满字段编造。

## E：实体关联

- 输入：实体提及、已知 ID、别名及上下文。
- 输出：mention 到 canonical entity 的映射与 memory_entity 关联；不确定映射可待确认。
- 实现：优先业务 ID 与明确别名；字符串/上下文辅助，不确定时保留多个候选。关系表可按需展开共享实体，无需所有记忆两两连边。
- 依赖/触发：P；有跨称呼或跨会话身份问题时。
- 降级：不确定实体不强制合并；保留原提及检索。
- 成本/验收：消解和邻居数量；检验别名能连通、同名不同人不混合。

## T：时间、变化与版本

- 输入：原始消息时间/时区、事件时间表达、修改或纠正事件。
- 输出：发生区间与提及时间；需要时另加有效范围、入库时间、版本及 supersedes 关系。
- 实现：相对时间以来源时间为锚；事件时间与属性有效期分开。区分信息后来改变、当时记录错误、后来才得知过去事件三种情况。
- 依赖/触发：P；历史查询、属性变化和冲突处理需要。
- 降级：不确定区间与未知开始时间保持显式，无法判定当前状态时说明冲突而非取最新一句。
- 成本/验收：历史存储与时态过滤；检验“当时发生什么”和“当时知道什么”所需的不同数据。

论文的 occurred_start/end 与 mentioned_at 不能自动替代完整双时态或历史版本实现。是否需要这种实现由业务查询决定。

## S：事实型实体摘要

- 输入：符合目标用途的有效底层事实/经历快照、实体范围与摘要用途。
- 输出：中立摘要、支持记录 ID、输入版本/摘要版本和刷新状态。
- 实现：按实体或明确任务生成派生视图；底层新增、纠正、撤回使相关摘要失效，后台重算，提交时校验输入版本。
- 依赖/触发：P 必需；E 可由固定 user_id 提供，T 在时态摘要中需要。触发是底层依赖变化，不是任意新回复。
- 降级：陈旧时读取底层记录或返回 freshness 信息；不能把缓存摘要假装成刚验证过的数据。
- 成本/验收：摘要调用、队列、依赖维护；检验来源可追溯、观点未变用户属性、旧任务未覆盖新结果。

“Agent 曾建议 X”可以进入交互摘要，仍须保留归属；用户能力/偏好档案是否需要它取决于用途。Opinion 内容不得作为某属性成立的直接证据。

## R：检索、融合与预算

- 输入：问题、范围/类型/时间约束、token 与可选延迟预算。
- 输出：预算内有序证据，含类型、来源、时间、支持关系及必要 freshness。
- 实现：按失败模式选结构化过滤、关键词、语义或关系通道；多路排名可用 RRF，再按收益采用重排。返回预算计算实际序列化文本，预留其他上下文和输出空间。
- 依赖/触发：P 与可查询数据；通道所需的 E/T/G 应由契约或现有系统提供。
- 降级：通道失败允许回退，保留强制过滤；若证据链不能完整装入，返回不足而不是省略限制制造完整答案。
- 成本/验收：候选数、重排延迟、token；检验漏检与跨事件证据覆盖，同时观测成本。

RRF 融合相关性，不验证真实；它可以复用同一证据，不能增加观点支持次数。论文的重排步骤是其实现，不是本技能所有场景的前置条件。查询规划可并行独立通道，图扩展等待种子命中。

## G：关系扩展

- 输入：种子命中、关系类型/方向/来源、跳数与扩展预算。
- 输出：关联证据及可解释路径，继续遵守范围/类型/时间约束。
- 实现：先实体邻居展开；需求证明需要时再接语义、时间、因果关系。限制跳数、每节点邻居数和总候选量，防止超级节点扩散。
- 依赖/触发：P + R + E 或其他有来源关系；直接检索确有多跳盲区才增加。
- 降级：预算耗尽返回部分证据和缺口；没有依据的关系不补成“因果”。
- 成本/验收：建边与查询扩展；检验路径支持解释、相邻时间不被当作因果。

## O：长期判断与修订

- 输入：新证据、已有判断、问题与必要的 Agent 行为配置。
- 输出：观点文本、适用条件、支持/反对证据、信念强度与修订历史。
- 实现：形成候选与证据强化分开；证据按原始事件去重；强反证既可改强度也可限定或撤销文本。没有新独立证据时不进行证据强化。
- 依赖/触发：P + R，必要时 T/E；确有持续建议/假设需求时采用。拒答或“信息不足”不创建 Opinion。
- 降级：不确定时保留候选/待评估状态；事实任务显式取事实，不使用观点替代证据。
- 成本/验收：评估调用、版本和审计；检验重复证据不强化、反证改变判断、事实表述不受人格配置改写。

论文示例强化规则为支持 +α、削弱 −α、矛盾 −2α、无关不变，并截断到 [0,1]。这是启发式信念强度，不是严格贝叶斯概率；适用条件变化可能要求重新表述并重评，而非机械减分。Agent 画像与用户偏好分开；稳定语气需求可用简单配置，无需引入完整观点系统。

## 最小数据与 API 示意

下面是工程设计字段，不是已核验 SDK；仅选实际需要的项：

```text
Source: id, scope, role, subject, payload/reference, mentioned_at
Memory: id, scope, subject_id, type, narrative, source_ids,
        claim_mode, occurred_start/end?, valid_from/to?, status, revision
Support: derived_id, source_or_memory_id, relation, original_evidence_key
Entity: id, scope, canonical_name, aliases
Observation: id, scope, entity_id, purpose, text, support_ids,
             input_revision, revision, freshness
Opinion: id, scope, text, conditions, belief_strength,
         support_ids, counterevidence_ids, revision
```

`claim_mode`、抽取质量与 Opinion 的信念强度是不同维度。`valid_from/to` 是属性适用期；事实在历史上有效而当前过时，与记录被撤回是不同状态。

```text
retain(scope, source_event, idempotency_key) -> accepted records, change events
recall(scope, query, filters, token_budget) -> labeled evidence, gaps, freshness
reflect(scope, query, evidence, agent_config?) -> answer, opinion candidates
refresh_observation(scope, entity_id, expected_input_revision) -> new revision
```

保存回答的事件由应用发起；`reflect` 的候选不等于已经落库，也不等于回答已被用户接受。实现契约应说明提交点。
